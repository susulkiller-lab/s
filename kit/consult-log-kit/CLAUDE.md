# 상담일지 정리 설치 키트

이 폴더는 직원이 자기 claude.ai 계정에 '상담일지 정리'(상담 내용을 일지 텍스트로 정리하고 기록을 보관하는 도구)를 설치하는 키트다. 사용자가 "상담일지 설치해줘", "설치해줘", "상담일지 만들어줘"라고 하면 아래 1~3을 그대로 수행한다. 사용자가 상담 기록을 붙여넣으며 "기록함에 넣어줘"라고 하면 4를 수행한다. 사용자는 개발자가 아니므로 결론부터 짧게 경어체로 안내하고, 기술 용어는 쓰지 않는다. 마크다운 강조는 쓰지 않는다.

## 1. 게시
Artifact 도구로 이 폴더의 consult-log.html을 게시한다. 파일 내용은 수정하지 않는다.
- icon: notebook
- description: 전화·대면 상담 내용을 칸별로 입력하면 AI가 원문 표현을 살려 정리하고, 상담 기록을 보관하며 경로별 접근 통계를 보여 주고 엑셀로 내보내는 상담일지 도구.
- capabilities(아래 JSON 그대로):
  {"sample": {}, "db": {"rules": [{"path": "consults", "read": "interact", "write": "interact"}]}, "downloads": true}
- 게시가 capabilities 때문에 거절되면 db나 downloads를 빼고 게시하지 않는다(db를 빼면 기록이 보관되지 않는다). 거절 사유를 사용자에게 그대로 알리고 관리자에게 문의하라고 안내한다. 사용자가 "기록 보관 없이 설치"를 명시적으로 원할 때만 뺀다.
- 이미 이 대화에서 게시한 적이 있으면 같은 파일 경로로 다시 게시해 주소를 유지한다.
- 이 도구는 외부 커넥터가 필요 없다. 커넥터 설치를 요구하지 않는다.

## 1-1. 갱신
사용자가 "상담일지 갱신해줘"라고 하며 본인 상담일지 주소를 알려 주면, 그 주소를 url로 지정해 consult-log.html을 다시 게시한다. 게시 전에 그 주소를 Artifact 도구의 read로 먼저 읽는다. capabilities는 1의 JSON과 같으면 생략해 저장된 선언을 유지한다. 기록(consults)은 갱신해도 그대로 남는다. 주소를 모르면 list(scope mine)에서 제목이 '상담일지 정리'인 것을 찾는다.

## 2. 동작 확인 (ArtifactData 도구를 쓸 수 있을 때만, 1회)
게시 직후 기록 저장소가 열렸는지 확인한다.
1. consults 컬렉션에 doc_id가 probe인 문서를 하나 쓴다(내용: {"name": "시험", "text": "설치 확인용"}).
2. 같은 컬렉션을 list로 읽어 그 문서가 보이는지 확인한다.
3. 확인되면 probe 문서를 if_version을 지정해 삭제한다.
4. 쓰기나 읽기가 실패하면 사유를 사용자에게 알린다. 성공하면 사용자에게는 "기록 보관 확인했습니다" 한 줄만 말한다.
ArtifactData 도구가 보이지 않으면 이 단계는 건너뛰고 사용자에게 알리지 않는다.

## 3. 안내
게시가 끝나면 사용자에게 다음만 알린다.
1. 상담일지 주소(즐겨찾기 권장). 앞으로는 Claude Code 없이 웹에서 이 주소로 쓴다. 본인만 열 수 있는 개인 도구다.
2. 정리하기를 처음 누를 때 Claude 사용 허용 창이 뜨니 허용한다.
3. 정리하기를 누르면 기록이 자동 보관된다. 다음 상담은 반드시 새 상담 버튼으로 시작한다.
4. 자세한 사용법은 사용설명서.txt에 있다.
5. 기존 상담 기록이 있으면 이 창에 붙여넣으며 "기록함에 넣어줘"라고 하면 된다.

## 4. 기록 가져오기 (기존 일지 텍스트를 기록함에 넣을 때)
대상은 상담일지 주소가 가리키는 아티팩트의 consults 컬렉션이다. 주소를 모르면 Artifact 도구의 list(scope mine)에서 제목이 '상담일지 정리'인 것을 찾고, 여러 개이면 사용자에게 묻는다. ArtifactData 도구가 보이지 않으면 ToolSearch로 불러온다.

### 변환 규칙
- 붙여넣은 문장은 고치지 않는다. 복사 과정에서 줄 사이에 생긴 빈 줄과 별표(**, ***)만 지운다.
- 적혀 있지 않은 값은 추측하지 않고 빈 문자열로 둔다. 일지의 "-"는 빈 칸이다. "모름", "수집안함", "성명불상"처럼 적힌 값은 그대로 넣는다.
- 경로(route)는 앱의 항목과 맞을 때만 그 이름으로 넣는다. 항목은 네이버, 구글, AI 툴(챗GPT 등), 홈페이지, 지인 소개이다. 맞지 않는 표기는 route를 기타로 하고 routeEtc에 적힌 그대로 넣는다. "물어보지 못함"처럼 경로를 알 수 없다고 적힌 건은 route와 routeEtc를 빈 문자열로 두고(통계에서 미상), 일지 텍스트의 경로 줄에는 적힌 표기를 그대로 둔다.
- 날짜와 괄호 요일이 맞는지 계산으로 검산한다. 맞지 않는 건은 저장하지 말고 사용자에게 확인한다.
- 연도나 시간이 없으면 사용자에게 묻는다. 맥락상 명백해 연도를 보정했다면 어느 건인지 반드시 보고한다.
- 질의와 답변이 구분되지 않은 메모는 q와 a를 비우고, text의 [상담 메모(질의·답변 구분 없이 적힌 원문)] 아래에 그대로 둔다.
- 방식이 없거나 불명확하면 사용자에게 묻는다. 화면의 집계는 대면이 아니면 전화로 센다.

### 문서 형식
컬렉션 consults, doc_id는 imp-날짜시각-순번(예: imp-20261118-1350-01)으로 하고 기존 문서와 겹치지 않게 한다. 필드는 아래와 같다.
- date: 2026-11-18 형식, time: 13:50 형식(없으면 빈 문자열), when: date와 time을 공백으로 이은 문자열
- method: "전화 상담" 또는 "대면 상담"
- route, routeEtc: 위 규칙
- name, phone, job, area: 이름, 전화번호, 직업, 거주지
- extra: 기타 당사자 정보, q: 질의 줄들, a: 답변 줄들
- text: 일지 전문. 아래 모양을 따른다. 기타 당사자 정보가 없으면 그 구역은 빼고, 빈 값은 "-"로 쓴다.
  [상담일지]
  방식: 전화 상담
  일시: 2026.11.18(수) 13:50
  경로: (적힌 경로)
  이름: ...
  연락처: ...
  직업: ...
  거주지: ...
  (빈 줄)
  [기타 당사자 정보]
  ...
  (빈 줄)
  [질의]
  ...
  (빈 줄)
  [답변]
  ...
- createdAt, updatedAt: 저장 시각(밀리초 숫자), source: "import"

### 저장과 보고
- 변환한 문서를 파일로 만들어 두고, ArtifactData의 batch(한 번에 최대 50건)로 file_path를 지정해 넣는다.
- 저장 후 사용자에게 보고한다: 넣은 건수, 경로별 건수, 비어 있는 항목이 있는 건, 보정하거나 사용자 확인이 필요한 건.
- 이미 있는 기록과 같은 상담이 겹쳐 들어가지 않도록, 사용자가 이전에 넣은 적이 있다고 하면 consults를 먼저 읽어 날짜·시간·이름·전화번호가 같은 건은 건너뛰고 보고한다.

## 금지
- consult-log.html을 고치거나 다시 쓰지 않는다. 문제가 있으면 사용자에게 관리자에게 문의하라고 안내한다.
- 상담일지를 공개 링크로 공유하라고 권하지 않는다. 이름과 전화번호가 저장된다.
- 사용자가 요청하지 않은 기록을 지우거나 덮어쓰지 않는다.
