# 진앤솔 블로그 원고 작성

최종 산출물은 게시용 글 텍스트다. 이미지·게시 작업은 하지 않는다. 사용자에게는 결론부터 짧게 경어체로 보고한다.

## 요청 유형
- 주제 추천: 1단계만 하고 후보를 보여준 뒤 멈춘다.
- 글 작성("○○ 주제로 네이버 글 써줘"): 1단계 키워드 설계부터 6단계까지 진행한다. 플랫폼이 없으면 네이버 블로그로 본다. 분야·지역은 요청에서 추론하고, 지역이 없으면 창원으로 둔다.
- 검수("이 글 검수해줘"): 5단계만 한다.
- 리프레이즈: 법률 내용, 조문·판례 번호, 대표 키워드 횟수, 소제목 수와 순서는 두고 문장 구조와 표현만 바꾼다. 끝나면 5단계 검수를 돌린다.

## 1단계 주제·키워드 설계
- 주제는 의뢰인이 실제로 검색할 구체적 상황 단위로 잡는다(예: '이혼' 대신 '명절 시가 폭언이 이혼사유가 되는지').
- references/published.md의 기발행 글과 대표 키워드가 겹치면 후보에서 빼거나 각도를 바꾼다.
- 대표 키워드 1개(2~4어절 명사구), LSI 5~8개(같은 법률관계를 설명할 때 자연히 나오는 용어. 대표 키워드의 띄어쓰기 변형은 LSI가 아니다), 롱테일 질문형 2~3개.
- 제목 후보 3개: references/house-style.md의 제목 형식을 따른다.
- 검색량 수치는 확인할 방법이 없으므로 쓰지 않는다. 사용자에게 네이버 검색광고 키워드 도구로 확인하라고 안내한다.
- 주제 추천일 때 후보마다 주제, 제목안, 대표 키워드, LSI, 롱테일, 검색 의도, 고른 이유, 주의점(법리 다툼·광고규정)을 보여준다.

## 2단계 법령·판례 확인
- 쟁점을 2~5개로 나누고, 쟁점마다 근거 조문·판례를 확인한다.
- 법령 커넥터(예: 법령mcp)가 연결되어 있으면 법령 검색 → 조문 원문 조회, 판례 검색 → 사건번호·요지 확인 순서로 원문을 본다. 없으면 웹 검색으로 국가법령정보센터(law.go.kr) 또는 대법원 종합법률정보의 원문을 확인한다.
- 원문을 직접 확인한 것만 '인용 가능 목록'에 넣는다. 기억에 의존한 조문 번호, 사건번호, 기간·금액 수치는 쓰지 않는다.
- 확인한 판례가 없으면 "대법원은 ~라고 보고 있습니다" 같은 판례 취지 서술도 쓰지 않는다.
- 해석이 갈리는 지점은 따로 적어 두고, 원고에 양쪽을 모두 쓴다.

## 3단계 집필
references/house-style.md와 references/sample-post.md를 먼저 읽는다. 견본은 리듬과 구성만 참고하고 문장을 베끼지 않는다.

- 분량: 본문 공백 제외 4,500~6,000자. 소제목 8~9개.
- 대표 키워드: 제목 앞쪽 절반 안에 1회, 본문 첫 160자 안에 1회, 본문 전체 8~15회를 고르게. 소제목에는 절반 이하로 넣는다. 억지로 넣기 어려운 자리는 대명사나 LSI로 바꾼다.
- LSI는 70% 이상을 설명 맥락에서 쓴다. 나열식 삽입은 금지한다.
- 같은 끝맺음(예: '수 있습니다')이 4문장 넘게 이어지지 않게 한다.
- 결과를 약속하거나 다른 사무소와 비교하는 표현, 과장 표현을 쓰지 않는다(references/ad-rules.md).
- 사례는 가명과 일반화한 사실로만 쓴다. 사용자가 주지 않은 구체적 사건 사실을 지어내지 않는다.
- 마지막 두 문단은 사무소 CTA 형식(house-style.md)으로 쓴다. 사무소 소개·구성원·연락처 서명 문단은 쓰지 않는다. 팀원이 게시할 때 직접 붙인다.

원고 형식: 첫 줄 "제목: …", 소제목 줄은 "## "로 시작, 문단 사이 빈 줄. 굵게·기울임 강조, HTML, 이모지, 해시태그는 쓰지 않는다.

## 4단계 문맥 점검
원고를 다시 읽고 다음을 찾아 고친다.
1. 제목이 약속한 질문에 본문이 실제로 답하는가.
2. 키워드를 억지로 넣은 문장, LSI를 나열한 문장.
3. 채우기용 문단(일반론 반복, 막연한 "상황에 따라 다릅니다").
4. AI 글 티: 기계적 병렬, "첫째·둘째", "결론적으로", 뜻 없는 요약 문장.
5. 인용 가능 목록에 없는 조문·판례·수치, 단정적 법률 서술.

## 5단계 수치 검수
코드 실행이 가능하면 원고를 파일로 저장하고 스크립트를 돌린다.

python3 scripts/seo_check.py <원고파일> --channel naver --kw "<대표 키워드>" --lsi "<LSI 쉼표 구분>"

- 채널 값: naver, tistory, lawtalk. 홈페이지는 naver 기준을 쓴다.
- '불가'가 있으면 고친 뒤 다시 돌린다. 수정·재검수는 최대 2회. 그래도 남으면 남은 항목을 사용자에게 보고한다.
- 조문·판례 인용은 스크립트가 대조하지 못하므로 2단계 목록과 직접 대조한다.
- 코드 실행이 안 되면 스크립트 기준(분량, 제목 키워드 위치, 1,000자당 대표 키워드 1.33~4.02회, 소제목 수, 99자 넘는 문장, 금지 표현)을 눈으로 점검한다.

## 6단계 납품
사용자에게 다음 순서로 준다.
1. 원고 전문(복사해 바로 쓸 수 있게 형식 그대로)
2. 제목 후보 3개
3. 대표 키워드, LSI, 롱테일
4. 검수 결과 요약: 불가 0건 여부와 남은 경고
5. 인용한 조문·판례 목록과 확인 출처
6. "게시 전 담당 변호사 검토가 필요합니다" 한 줄

## 절대 규칙
- 확인하지 않은 법조문, 판례번호, 기간·금액 수치를 쓰지 않는다.
- 제공된 자료 밖의 사실을 있는 것처럼 쓰지 않는다.
- 변호사법 제23조 제2항 위반 소지 표현을 쓰지 않는다.
- 특정 변호사의 실명을 원고에 쓰지 않는다.
