판정 원칙은 셋입니다. 의뢰인 원 요구(1분 파악, 체크 쾌감과 즉시 반영, 도과·소홀 가시화, 업무 추가·제외, 문의 추적, 언제든 xlsx·docx)를 깨는 지적은 채택합니다. 같은 효과를 더 작은 구현으로 낼 수 있으면 수정 채택합니다. 범위만 늘리거나 요구와 어긋나는 지적은 기각합니다.

- 반복 업무 목록(위·아래 버튼으로 순서), [업무 추가]: 이름(20자), 채널, 주기(매일·매주·매월), 단위(편·건·회), 목표 수량, 기한(매주는 요일, 매월은 날짜 또는 마지막 영업일), 담당, 링크로 체크, 시작일.
- 업무 편집: 목표·담당·기한·링크 변경 → 적용 시작(기본 다음 주 월요일, 매월은 다음 달 1일, '오늘부터' 선택 가능, 지난 날짜 불가). 쉬기(기간), 그만하기(종료일, 기록 0건이면 삭제).
- 휴무일: 목록에서 추가·삭제(지난 날짜는 경고 후 허용).
- 팀원: 호칭 목록, 활성·비활성, 순서, 쉬는 날 대리 입력.
- [초기 업무 불러오기](업무가 0개일 때만): 5장 표를 tasks에 쓰고 inq/probe를 만듦.

첫 접속 시트
- user.id()가 있고 members/{id}가 없으면 '화면에 보일 이름을 적어 주세요(예: 김주임)' → members/{id} 생성.

- 첫 쓰기가 invalid_argument로 거절되면 보기 전용과 '기록 권한이 없는 계정이에요'.

## 3. 판정 산식 확정본

### 3.1 시간 기준

- 날짜는 모두 Intl.DateTimeFormat('en-CA', {timeZone: 'Asia/Seoul'})로 만든 'YYYY-MM-DD' 문자열(한국 날짜)입니다. toISOString().slice(0,10)은 쓰지 않습니다.
- 기록 시각 at은 ISO 문자열로 저장하고 비교·표시 때 한국 시각으로 바꿉니다.
- 주는 ISO 주(월~일)이고 키는 'YYYY-Www'(주 연도 기준, 주 번호 두 자리)입니다. 2026년은 53주가 있습니다(2026-W53 = 2026-12-28~2027-01-03).
- 달은 한국 날짜의 연-월입니다.
- 하루는 00:00(한국 시간)에 바뀝니다. 자정에 열려 있는 화면은 다시 그리기만 하고 아무것도 쓰지 않습니다.

### 3.2 영업일, 휴무, 휴가

| 개념 | 정의 | 효과 |
|---|---|---|
| 영업일 | 월~금 중 config.holidays에 없는 날(가정: 주말 발행 없음) | 매일 업무 목표가 생기는 날 |
| 휴무일 | 공휴일(2026·2027년치 초기값)과 사무소 휴무(사무장 입력) | 전원 목표 0 |
| 쉬는 날 | members/{uid}.off의 날짜(휴가·반차 등, 본인 또는 사무장 입력) | 그 사람이 담당인 업무만 목표 0. '팀 공동' 업무는 영향 없음 |
| 건너뛰기 | (업무, 날짜) 단위, 사유 코드 필수 | 그날 그 업무 목표 0. 매주·매월은 그 기간 목표 0 |
| 쉬기 | tasks.pauses 기간 | 그 기간 목표 0, 오래 못 함 계산에서 제외 |
| 활성 | startAt ≤ d, endAt이 없거나 d ≤ endAt, 쉬기 아님 | 목표 계산의 전제 |

### 3.3 목표 T

```
판본  v(X, d) = X.versions 중 from ≤ d 인 마지막 판본

매일  T(X, d) = v(X, d).qty   d가 영업일이고 X 활성이고 담당이 쉬지 않고 건너뛰지 않았을 때
             = 0             그 밖

매주  기한일 = 그 주의 v.due 요일. 휴무면 그 주 마지막 영업일
      T(X, w) = v(X, 기한일).qty   그 주 영업일 중 X가 활성이고 담당이 쉬지 않는 날이 하루라도 있고,
                                    이번 주 건너뛰기가 없을 때 (휴일이 끼어도 목표는 그대로)
             = 0                   그 밖
      시작 주: startAt이 그 주 기한일 이전이면 그 주부터

매월  기한일 = v.due(날짜 또는 last). 휴무이거나 그 달에 없는 날이면 그 이전 마지막 영업일
      T(X, m) = v(X, 기한일).qty   그 달 활성 영업일이 하루라도 있고 이번 달 건너뛰기가 없을 때
      시작 달: startAt이 그 달 기한일 이전이면 그 달부터

지시  목표 = qty, 기한 = due(등록 뒤 휴무로 바뀌어도 그대로), 취소된 지시는 모든 계산에서 제외
```

### 3.4 완료 수와 배정

```
유효 기록: void가 없는 entries. 같은 키가 여러 문서에 있으면 at이 가장 이른 것 하나만 셈

업무 X, 몫 날짜 d의 수
  링크 업무:  cnt(X, d) = max(U, L)   U = 링크 기록 수, L = 링크 없는 체크의 n 합
  그 밖:      cnt(X, d) = n 합

매일 업무의 주 안 배정 (주 w의 월~일 각 날짜 d)
  1. F(d) = min(T(d), cnt(d))
  2. s = Σ max(0, cnt(d) − T(d))            남는 수
  3. w의 날짜를 이른 순으로 돌며
       a = min(s, T(d) − F(d));  F(d) += a;  s −= a
  4. 마지막에 남은 s는 초과분 ('+s 더 함', %에 넣지 않음)

매주  C(X, w) = 몫 날짜가 w에 든 cnt 합
매월  C(X, m) = 몫 날짜가 m에 든 cnt 합
지시  done(Z) = done 맵의 n 합(void 제외)
```

- 늦게 한 만회분은 이른 부족분을 채우고, 미리 한 일은 뒷날 몫이 됩니다(기술-10). 주말에 한 일도 평일 부족분이나 뒷날 몫을 채웁니다.
- 누를 때 저장하는 몫 날짜(for): 밀린 행은 배정 후 부족분이 남은 가장 이른 날, 오늘 행은 오늘, 이번 주 안에 행은 오늘, 붙여넣기는 날짜 줄(없으면 오늘).
- 배정은 저장하지 않고 늘 위 규칙으로 다시 계산합니다. 두 사람이 같은 부족분을 동시에 채워도 넘친 수가 다음 부족분으로 흘러가므로 이중 배정이 생기지 않습니다(기술-3).

### 3.5 오늘 게이지

```
t0 = 오늘 00:00(한국 시간)
A0 = at < t0 인 기록만으로 낸 배정 (t0 이후의 void는 무시)
A  = 지금 모든 기록으로 낸 배정
범위: 팀 = 활성 업무 전부와 열린 지시 전부
      나 = 담당이 나 또는 '팀 공동'인 업무와 지시

매일 업무 X (이번 주 안)
  B0(X) = Σ_{이번 주, d < 오늘} (T(d) − F0(d))         아침 기준 밀린 수
  B(X)  = Σ_{이번 주, d < 오늘} (T(d) − F(d))          지금 밀린 수
  남은0(X) = (T(오늘) − F0(오늘)) + B0(X)
  채움(X)  = (F(오늘) − F0(오늘)) + max(0, B0(X) − B(X))

매주·매월 업무 Y (현재 주·달, 기한일 ≤ 오늘)
  남은0(Y) = max(0, T − C0),  채움(Y) = min(남은0(Y), max(0, C − C0))

지시 Z (열림, 기한 ≤ 오늘)
  남은0(Z) = max(0, qty − done0),  채움(Z) = min(남은0(Z), max(0, done − done0))

분모 D = Σ 남은0      분자 N = Σ 채움
표시 % = floor(100 × N / D),  N = D 일 때만 100
```

- 뜻은 '오늘 아침에 남아 있던 할 일 가운데 끝낸 비율'입니다. 분모는 하루 동안 고정되고 밀린 행·오늘 행·오늘 마감 지시 어느 것을 눌러도 1씩 오릅니다(UX-1).
- 행과 숫자를 맞춥니다. 밀린 행의 원 개수는 B0(X), 찬 원은 B0(X) − B(X)입니다. 오늘 행의 원 개수는 T(오늘), 찬 원은 F(오늘)이고 아침 전에 미리 채워진 몫은 보조줄에 '1편은 월요일에 미리 함'으로 표시합니다(게이지 분모에는 없음).
- 오늘 기록을 '하나 빼기'로 지우면 분자가 내려갑니다. 아침 전 기록을 지우면 분모는 그대로이고 그 행에 부족분이 다시 생깁니다.
- 분모가 0이면 2.3절 빈 상태 문구를 씁니다.
- 지난주 마지막 영업일의 기록 대기분은 게이지에 넣지 않습니다(주가 바뀌면 이월하지 않는 원칙).

### 3.6 기간 성과(기록 탭·보고서)

```
주 w   N = Σ매일 Σ_{d∈w} F(d) + Σ매주 min(C, T) + Σ_{지시, 기한∈w} min(done, qty)
       D = Σ매일 Σ_{d∈w} T(d) + Σ매주 T          + Σ_{지시, 기한∈w} qty
달 m   매일은 d∈m 인 F·T, 매주는 기한일이 m에 든 주, 매월 업무, 기한이 m에 든 지시
일 d   매일 업무의 F(d)·T(d)와 기한이 d인 지시
% = floor(100 × N / D),  미달 = D − N (기간이 끝난 뒤)
```

- 첫 화면 '이번 주'는 N/D와 'D − N개 남음'만 보이고 %는 기록 탭에서 봅니다(K1). 아직 오지 않은 날의 목표도 분모에 들어갑니다.
- 기한이 지난 주의 밀린 지시는 그 주 분모에만 들고, 이후 주에는 '챙길 것'과 오늘 게이지에만 나옵니다.
- 1편, 1건, 1회를 모두 1개로 셉니다(초안 유지).

### 3.7 기록 대기, 밀림, 미달

```
유예 시각 g(d) = d 다음 첫 영업일의 12:00(한국 시간)
부족분이 생긴 날 d: 매일 업무는 그날, 매주·매월·지시는 기한일
상태 = 지금 < g(d) 이면 '기록 대기'(회색), 아니면 '밀림'(빨강)
```

| 종류 | 밀림으로 보이는 기간 | 그 뒤 |
|---|---|---|
| 매일 | 유예 이후 그 주 일요일까지 | '지난주 미달'로 기록 탭에만 남음(이월 없음) |
| 매주 | 기한일 유예 이후 그 주 일요일까지. 금요일 기한이면 유예가 다음 주 월요일 정오라 주중 밀림이 뜨지 않고 바로 '지난주 미달' | 미달 |
| 매월 | 기한일 유예 이후 그 달 말일까지 | 미달 |
| 지시 | 유예 이후 끝나거나 취소될 때까지, 'n일 지남'(달력일) | 계속 |

- 경고등 숫자는 빨강 밀림인 행(업무) 수입니다. 회색 기록 대기는 세지 않습니다.
- '늦게 기록'은 기록 시각의 한국 날짜가 몫 날짜보다 2일 이상 뒤인 기록이며 사무장 엑셀 열로만 남깁니다.

### 3.8 오래 못 함

- 대상: 반복 업무. 매일·매주 업무는 시작 7일 뒤, 매월 업무는 시작 1개월 뒤부터 판정합니다.
- last(X): 유효 기록의 몫 날짜 가운데 가장 늦은 날. 읽은 14주 안에 없으면 '14주 넘게 기록 없음'.
- G(X): last 다음 날부터 어제까지의 영업일 가운데 X가 활성이고, 담당이 쉬지 않고, 건너뛰지 않은 날 수.
- 기준(코드 상수, 가정): 매일 3, 매주 10, 매월 25. G가 기준 이상이면 '오래 못 함'.
- 표시: 행 배지는 밀림 배지가 없을 때만 '오래 못 함 · G일째'. 기록 탭 '챙길 것'에 '마지막 10/14 · 영업일 9일째', 정렬은 G ÷ 기준이 큰 순.
- 저조율(최근 4주 50% 미만)은 2단계입니다.

### 3.9 기록할 수 있는 기간과 주간 마감

- 팀원: 몫 날짜가 이번 주이거나, 오늘이 월요일이면 지난주까지. 오늘보다 뒤인 날짜는 고를 수 없습니다(뒷날 몫은 넘침 배정으로만 생김).
- 사무장: 모든 날짜. 기간이 지난 기록은 상세에 '정정' 표시.
- 주간 마감: 사무장이 기록 탭 지난주 화면의 [주간 마감]을 누르거나 주간 보고 워드를 저장하면 closed/{YYYY-Www}에 요약 스냅숏을 씁니다. 마감 뒤 수치가 바뀌면 사무장 화면에 '마감 뒤 바뀜', 다시 마감할 수 있습니다. 화면과 보고서는 늘 다시 계산하고, 스냅숏은 감사와 백업 대조에 씁니다.
- 월간 마감: 월간 보고 워드를 저장할 때 closed/{YYYY-MM}.

### 3.10 템플릿 변경 시 과거 기록

- 목표·담당·기한·링크 여부 변경은 versions에 {from, …}을 더합니다. 기본 from은 다음 주 월요일(매월 업무는 다음 달 1일)이고 '오늘부터'를 고를 수 있습니다. 지난 날짜 from은 받지 않습니다.
- 주기(매일·매주·매월) 변경은 받지 않습니다. 그만하기 후 새 업무로 만듭니다.
- 쉬기·그만하기·휴무일은 오늘 이후로만 넣고, 지난 날짜는 사무장 경고 확인 후 허용합니다. 마감된 주가 바뀌면 '마감 뒤 바뀜'이 뜹니다.
- 그만한 업무의 기록은 보존하고 기록이 0건일 때만 삭제합니다.
- 업무 이름 변경은 판본 없이 바로 바뀝니다(지난 표에도 새 이름).

## 4. 데이터 모델 확정본

### 4.1 컬렉션

| 경로 | 문서 단위 | 필드 | 쓰기 | 연간 문서 수(가정: 팀원 5명, 월 문의 100건) |
|---|---|---|---|---|
| config/main | 1개 | holidays{날짜: 이름}, updatedAt, updatedBy | 소유자 | 1 |
| members/{uid} | 팀원 1명 | name(호칭, 10자), active, order, off{날짜: 사유코드}, createdAt, updatedAt | 본인({self}), 소유자 | 10 미만 |
| tasks/{taskId} | 반복 업무 1개 | title(20자), ch, kind(daily·weekly·monthly), unit(편·건·회), link, versions[{from, qty, due, assignee}], pauses[{from, to}], startAt, endAt, order, createdAt, updatedAt | 소유자 | 30 미만 |
| specials/{id} | 지시 1건 | title(40자), src(meeting·order·etc), srcDay, assignee, qty, due, status(open·cancelled), done{키: {by, at, day, n, void}}, createdBy, createdAt, cancelledBy, cancelledAt, updatedAt | 참여자 이상 | 약 200 |
| logs/{uid}/w/{YYYY-Www} | 팀원별 몫 주 1개 | week, entries{키: {t, for, at, n, url, title, ch, b, void}}, skips{업무id_날짜: {why, at, void}}, createdAt | 본인({self}), 소유자 | 260 |
| inq/{YYYY-MM}/items/{id} | 문의 1건 | day, type(call·visit·booking), path, term, field, ref, review(na·todo·asked), askedDay, by, createdAt, updatedAt | 참여자 이상, 읽기도 참여자 이상 | 1,200 |
| inq/probe | 1개 | ok | 소유자가 초기 업무 불러오기 때 생성 | 1 |
| notes/{YYYY-Www} | 주 1개 | focus(60자), memo(1,000자), updatedAt, updatedBy | 참여자 이상 | 52 |
| closed/{YYYY-Www 또는 YYYY-MM} | 주·달 1개 | summary{업무별 T·N, 발행 수, 문의 수, 지시 수}, closedAt, closedBy | 소유자 | 64 |

- 합계 연 약 1,800개로 계약 상한 25,000개 대비 13년 이상입니다.
- uid는 user.id() 값 그대로(불투명 토큰)이며 화면에 보이거나 가공하지 않습니다. assignee는 uid 또는 'team'.
- entries의 키: 링크 기록은 2.6절 정규화 키, 그 밖은 'x'와 무작위 10자.
- void는 무효로 만든 시각(ISO)입니다. 3.5절의 아침 기준 계산이 t0 이후 void를 무시하기 위해 불리언 대신 시각을 씁니다.
- b는 붙여넣기 묶음 id, ch는 채널 코드(lawtalk, tistory, naver, place, shorts, homepage, press, column, etc), why는 사유 코드(leave, out, outage, etc).
- logs 주 문서는 몫 날짜의 주에 둡니다. 지난주 금요일분을 월요일에 기록하면 지난주 문서에 들어갑니다.
- 문의는 day의 달 문서 아래에 둡니다. 10/31 문의를 11/2에 옮겨 적으면 inq/2026-10 아래입니다.
- 프로필 이름은 저장하지 않습니다. members.name은 본인이 입력한 팀 내 호칭입니다.
- 배열 필드(versions, pauses)는 소유자 한 사람만 쓰므로 통째 교체 문제가 없습니다. 여러 사람이 쓰는 필드는 모두 객체 맵입니다.

### 4.2 선언과 접근 규칙

```json
{
  "db": {"rules": [
    {"path": "", "read": "view", "write": "interact"},
    {"path": "config", "write": "owner"},
    {"path": "tasks", "write": "owner"},
    {"path": "closed", "write": "owner"},
    {"path": "members", "read": "view", "write": "owner"},
    {"path": "members/{self}", "write": "interact"},
    {"path": "logs", "read": "view", "write": "owner"},
    {"path": "logs/{self}", "write": "interact"},
    {"path": "inq", "read": "interact", "write": "interact"}
  ]},
  "user": {"scopes": ["profile"]},
  "downloads": {}
}
```

- 계약: {self} 규칙의 접두 경로(members, logs)에는 read와 write를 모두 적어야 게시됩니다. 접두 경로를 read view로 열어 서로의 기록을 읽고, write owner로 두어 남의 기록은 소유자만 정정합니다.
- 계약: owner는 게시한 계정 하나입니다. 공유 메뉴에서 '소유자'로 지정한 사람은 admin이라 owner 경로를 쓰지 못합니다.
- 계약: 조직 밖 편집자는 공개 링크가 켜지면 view로 떨어집니다. 공개 링크는 쓰지 않습니다.
- specials와 notes는 루트 규칙(읽기 view, 쓰기 interact)을 따릅니다. 지시 취소·편집 제한은 화면 수준이며 주간 백업 차이로 사후 확인합니다(기술-17).
- 규칙은 재게시로 바꿀 수 있지만 소유자는 바꿀 수 없습니다. 00 문서 분기 1(관리 담당 소유)로 가면 config·tasks·closed·members 접두 규칙의 write를 admin으로 바꾸고 화면에서 사무장·관리 담당만 관리 화면을 보게 합니다.
- sample, room, mcp, files는 선언하지 않습니다.

### 4.3 쓰기 규약

1. 화면 상태는 구독 스냅숏에 아직 보내지 않은 내 변경(대기열)을 겹친 것입니다. 누르면 대기열에 넣고 즉시 다시 그립니다(0.1초 기준).
2. 문서마다 쓰기는 한 번에 하나입니다. 앞 쓰기가 끝나면 대기열의 같은 문서 변경을 update 한 번으로 묶어 보냅니다(연속 체크 묶음, 계약의 '문서당 한 번에 하나' 규칙).
3. logs 주 문서의 첫 쓰기: get → 없으면 set({week, createdAt, entries: {…}, skips: {}}), 있으면 update. set 직후 다시 get해 내 키가 빠졌으면 update를 한 번 더 합니다(두 기기가 동시에 문서를 만든 경우).
4. 추가는 update({entries: {키: 항목}}), 빼기는 update({entries: {키: {void: 시각}}}). 지시 완료는 specials/{id}에 update({done: {키: {…}}}).
5. 렌더 코드, 스냅숏 콜백, 타이머, 자정 전환에서는 쓰지 않습니다.
6. 오류 처리(계약 코드표 기준)

| 코드 | 처리 |
|---|---|
| invalid_argument(쓰기) | 권한 없음 또는 형식 오류. 대기열 원복, 해당 입력을 보기 전용으로 바꾸고 '기록 권한이 없는 계정이에요' |
| resource_exhausted | 대기열 유지, 3초 뒤 1회 재시도, 실패하면 원복과 '잠시 뒤 다시 눌러 주세요' |
| quota_exceeded | 원복, '저장 공간이 찼어요. 관리 담당에게 알려 주세요' |
| unavailable(쓰기) | 0.5~1.5초 무작위 대기 후 1회 재시도, 실패하면 원복과 '저장하지 못했어요' |
| unavailable(구독 오류 콜백) | 다리가 끊긴 경우. 2·4·8초…최대 60초 간격으로 새 onSnapshot, 머리줄에 '다시 연결하는 중이에요' |
| revoked | 입력을 모두 숨기고 보기 전용 |
| 그 밖의 코드 | unavailable과 같게 |

원고실의 permission_denied 분기는 계약에 없는 코드라 쓰지 않습니다(기술-12).

7. 두 기기 병합 시험(제작 1차 마지막 날): 같은 계정으로 PC와 휴대폰에서 같은 주 문서에 서로 다른 키를 1초 안에 각각 기록하고 두 키가 모두 남는지 10회 확인합니다. 하나라도 사라지면 문서 단위를 팀원별 하루(logs/{uid}/d/{날짜}, 연 1,250개)로 줄이고 쓰기 전에 get을 더합니다.

### 4.4 읽기와 구독

| 대상 | 방식 | 구독 수 |
|---|---|---|
| config/main | 문서 구독 | 1 |
| members | 컬렉션 구독 | 1 |
| tasks | 컬렉션 구독 | 1 |
| specials | orderBy('createdAt', 'desc').limit(300) 구독 | 1 |
| logs/{uid}/w(활성 팀원마다) | where('week', '>=', 13주 전 키) 구독 | 팀원 수(10 이하) |
| notes/{이번 주} | 문서 구독 | 1 |
| inq/{이번 달}/items, inq/{지난달}/items | 문의 탭을 처음 열 때 구독 | 2 |
| inq/probe | 시작 때 get 1회 | 0 |
| closed, 14주보다 오래된 logs, 지지난 달 이전 문의 | 기록·문의 탭에서 그 기간을 열 때 get | 0 |

- 구독 합계 18 이하로 계약 상한 64보다 훨씬 적습니다.
- 'YYYY-Www'는 주 번호가 두 자리라 문자열 비교로 순서가 맞습니다.
- inq/probe가 보이지 않으면(열람 전용) 문의 탭을 숨겨 '0건'을 그리지 않습니다.

### 4.5 기술 비판 대응 요약

| 문제 | 해결 |
|---|---|
| 동시 쓰기로 배열 기록 소실(기술-3) | entries·skips·done·off를 객체 맵으로, update 재귀 병합, 문서별 쓰기 직렬화, 병합 시험과 대체안 |

### 4.6 예외 분기(신원 없는 팀원)

- 1명: 기본 구조를 유지하고 그 사람 몫은 당번이 붙여넣습니다. 진척은 담당 기준이라 정확합니다.
- 2명 이상: logs를 logs/{memberKey}-{YYYY-Www}(루트 규칙, 참여자 쓰기)로 바꾸고, members는 소유자가 만들며, 첫 접속에서 명부를 골라 기기에 기억합니다. 기록에 user.id()가 있으면 함께 남기고 다르면 '대신 기록'으로 표시합니다. 덮어쓰기 위험은 감수하고 주간 백업 차이로 확인합니다.

- 5번은 제목에 '성공사례'가 있어야 판별되므로, 링크만 붙여넣으면 3·4번으로 들어갈 수 있습니다. 미리보기에서 바꿀 수 있습니다.
- 수량이 팀 인원 대비 적정한지는 의뢰인이 판단합니다. 1분 시험은 이 수량 데이터로 합니다.

### 6.3 저장하지 않는 것

- 이름, 전화번호, 주소, 주민등록번호, 이메일, 사건 내용, 상담 시각(날짜만 저장), 자유 메모 칸(두지 않음).
- 검색어·참조번호·회의 메모 입력 차단: 공백·하이픈·점·괄호를 지운 뒤 0 또는 +82로 시작하는 9~12자리 숫자열, 6자리-7자리(뒤 첫 자리 1~4) 주민등록번호 형태가 있으면 저장하지 않고 이유를 표시합니다.
- 이름은 자동으로 거를 수 없으므로 시트 상단에 '이름·연락처·사건 내용은 적지 않아요'를 고정합니다.
- 문의 상세는 참여자 이상만 읽습니다(규칙 inq read interact). 열람 전용 사용자에게는 탭이 보이지 않습니다.
- 문의 원장 엑셀 시트는 사무장 화면에서만 만들 수 있습니다(화면 수준 제한). 대표에게는 월간 보고 워드의 집계만 갑니다.
- 도입 전 대표 승인 1쪽: 수집 항목(위 표), 보관 위치(claude.ai 업무판 저장소, 사무소 저장소의 주간 백업, 사무소 공용 저장 위치의 월간 엑셀), 열람자(팀원·문의 담당·사무장), 보존 기간(가정: 파일럿 판정 때 정함).

- 버튼을 누를 때 스크립트를 넣어 불러옵니다(첫 화면 속도 보호). 이 환경에서는 CDN 직접 조회가 프록시에 막혀 실제 로드는 0주 접속 확인 페이지에서 시험합니다. 동적 삽입이 막히면 head에 defer로 고정 로드합니다.
- 워드 글꼴: 런 글꼴의 동아시아 글꼴을 '맑은 고딕'으로 지정합니다(파일에 글꼴이 들어가지 않으므로 보는 기기 글꼴로 대체될 수 있음).
- 저장: downloads.save({filename, data: Blob}). 결과별 처리는 아래와 같습니다.

| 결과 | 처리 |
|---|---|
| saved | '저장했어요' 토스트 |
| declined | 아무 안내 없이 종료(자동 재시도 금지) |
| rate_limited | '잠시 뒤 다시 눌러 주세요' |

| unavailable, not_granted 등 | 저장 버튼을 숨김 |

- 확인 창은 한 번에 하나라 저장 중 다른 저장 버튼을 잠급니다.

## 9. 백업과 인수인계

### 9.1 주기와 방법

| 주기 | 누가 | 방법 | 보관 위치 |
|---|---|---|---|
| 주 1회(월요일 주간 마감 뒤) | 관리 담당 | Claude Code에서 '업무판 백업해줘' → ArtifactData로 전 컬렉션을 읽어 JSON 저장 → tools/dashboard_sync.py로 지난 백업과 차이 요약, published.csv 동기화 → 사용자가 요청하면 커밋 | 저장소 data/dashboard/backup/{YYYY-Www}/ |
| 월 1회(월간 보고 때) | 사무장 | 지난달 엑셀(사무장 저장)을 내려받음 | 사무소 공용 저장 위치 |
| 수시(플랫폼 변경 공지, 소유자 교체 전) | 관리 담당 | 주간 백업과 같은 절차 즉시 실행 | 저장소 |

- 읽는 범위: config/main, members, tasks, specials, notes, closed, 팀원마다 logs/{uid}/w, 시작 달부터 inq/{YYYY-MM}/items. 관리 담당은 편집자(admin)라 inq를 포함해 모두 읽을 수 있습니다.
- 차이 요약에 넣을 것: 마감된 주의 수치 변화, 반복 업무 정의 변경, void 처리된 기록, 지시 취소, 다른 사람 담당 지시 편집. 사무장에게 한 줄로 보고합니다(4.5절 남는 위험의 사후 확인).
- published.csv 동기화: 백업의 링크 기록 중 csv에 없는 주소를 tools/ledger.py add로 넣습니다(channel은 lawtalk·naver·tistory만, main_kw는 빈칸, title은 기록 제목). 이로써 CLAUDE.md 5단계의 '발행했다고 알려오면 기록'은 주간 동기화로 바뀝니다(구현 때 CLAUDE.md 갱신).
- 저장소가 비공개라는 전제입니다(0주 확인). 문의 백업에도 식별정보는 없습니다.

### 9.2 복원 절차와 시험

1. 복원 대상 아티팩트를 엽니다. 실제 복원은 소유자 계정의 Claude Code가 해야 합니다(owner 경로와 남의 logs는 소유자만 쓸 수 있음).
2. ArtifactData batch로 JSON을 문서별 set합니다(컬렉션 순서: config, tasks, members, specials, notes, closed, logs, inq).
3. 기록 탭 지난 3주 수치를 closed 스냅숏과 비교해 일치를 확인합니다.
- 복원 시험(파일럿 3주 차): 관리 담당 소유의 시험 아티팩트에 최신 백업을 복원하고 3번 확인을 합니다. 소요 시간을 기록합니다.
- 주의: user id는 소유 조직 범위 안에서만 같습니다. 소유자가 다른 조직으로 바뀌는 복원이면 팀원이 새 주소에서 첫 접속 등록을 한 뒤 호칭으로 옛 uid와 새 uid를 짝지어 logs 경로와 assignee를 바꿔 넣습니다.

### 9.3 인수인계

| 상황 | 할 일 |
|---|---|
| 팀원 합류 | 편집자(조직 밖) 또는 참여자(같은 조직)로 초대 → 첫 접속 이름 등록 → 사무장이 담당 지정 |
| 팀원 퇴사 | 공유 해제, members.active 끔, 담당 재지정. 기록은 보존 |
| 관리 담당 교체 | 새 담당을 편집자로 초대, 저장소 권한 부여, 주간 백업 1회 동행 |
| 사무장 교체·퇴사 | 소유자 이전 방법이 계약에 없으므로 즉시 백업 → 새 소유자 계정으로 새 아티팩트 게시 → 9.2 복원 → 옛 주소 안내. 옛 아티팩트는 확인 기간 뒤 소유자가 삭제 결정 |
| 문의 당번 교대 | 주 단위, 기록 탭 회의 메모에 다음 당번 이름 |

- 삭제 금지: 업무판 아티팩트는 소유자만 지울 수 있고 지우면 데이터가 함께 사라집니다. 도입 공지에 적습니다.
- 공개 링크 금지: 켜면 조직 밖 편집자의 쓰기가 끊기고 노출 범위가 넓어집니다.

### 10.2 메신저 보고 전환

### 10.4 중단·축소 기준

- 3주 차 말 기록률 70% 미만: 원인(입력 부담, 휴대폰, 판정 불신)을 확인하고 '당번 하루 1회 붙여넣기' 단일 방식으로 축소합니다.
- 3주 차 말 문의 누락률 30% 이상: 문의 기능을 빼고 업무 체크만 남기거나 문의만 구글 시트로 옮기는 안을 의뢰인과 검토합니다.
- 0주 실측에서 마케팅 팀원 과반이 쓰기 불가: 제작 전에 구글 시트안 전환을 검토합니다.

### 10.5 도입 공지에 넣을 것

1. 공식 기록은 업무판, 단체방은 알림. 원고실 발행 처리는 선택
2. 팀원 화면에는 팀 합계와 본인 것만 보이고, 개인 평가에 쓰지 않음(의뢰인 결정 시). 다만 데이터는 팀원끼리 읽을 수 있는 구조임
3. 문의에는 이름·연락처·사건 내용을 쓰지 않음
4. 업무판 삭제와 공개 링크 켜기 금지, 페이지 재게시는 관리 담당만
5. 기한 다음 영업일 정오까지는 '기록 대기'이니 그 전에 붙여넣으면 빨강이 뜨지 않음
