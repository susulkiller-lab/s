# 마케팅팀 업무판 기획 초안 (01)

- 작성일: 2026-10-27(화)
- 작성: 최초 기획 에이전트
- 상태: 비판 검토 전 초안. 수량·기준값 중 근거가 없는 것은 모두 '가정'으로 표시했습니다.
- 가칭: 진앤솔 업무판

## 0. 결론

1. claude.ai 아티팩트로 '진앤솔 업무판'을 원고실과 별도 페이지로 만듭니다. 원고실의 공용 DB, user, 디자인 토큰, 단일 HTML 운영 방식을 그대로 재사용하며 추가 비용이 없습니다.
2. 입력은 지금 습관을 그대로 씁니다. 메신저 단체방에 올리는 일일 발행 보고 텍스트를 업무판에 붙여넣으면 링크를 읽어 채널별 체크가 자동으로 올라갑니다.
3. 첫 화면 '오늘'은 숫자 3개(오늘 %, 이번 주 %, 밀린 일 수)와 할 일 카드만 보여 줍니다. 체크하면 0.1초 안에 숫자와 막대가 오릅니다.
4. 밀림(도과)과 오래 못 함(소홀)을 구체적 산식으로 판정합니다(5.3절). 문의 기록에는 이름과 전화번호를 저장하지 않습니다.
5. 엑셀(xlsx)과 워드(docx)는 브라우저에서 바로 만들어 저장합니다. 엑셀의 발행 목록 시트는 data/published.csv와 같은 열 순서를 씁니다.
6. MVP는 화면 4개와 관리 화면 하나입니다. 구현에 3~5영업일, 파일럿에 2주를 잡았습니다(가정). Claude 자동 요약, 원고실 연동, 접속자 표시는 2단계로 미룹니다.

### 핵심 결정과 대안

| 결정 | 검토한 대안 | 선택 이유 |

| Claude 요약(sample)은 2단계 | MVP에 포함 | 공유받은 원고실 화면에서 sample이 열리지 않은 운영 사례가 있습니다(2026-09-30 커밋) |

## 1. 한 줄 정의와 성공 기준

한 줄 정의: 마케팅팀이 매일·매주 할 일과 광고 문의 유입을 한 화면에서 체크하고 실시간으로 공유하며, 언제든 엑셀·워드로 뽑는 팀 현황판입니다.

성공 기준은 파일럿 2주가 끝날 때 아래 표로 판정합니다.

| 번호 | 기준 | 측정 방법 | 합격선 |
|---|---|---|---|
| 1 | 1분 이해 | 처음 보는 5명(팀 밖 1명 이상 포함)에게 예시 데이터를 넣은 '오늘' 화면을 보여 주고 3가지를 묻습니다: 오늘 남은 일 개수, 이번 주 진척 %, 밀린 일 이름 | 5명 전원이 60초 안에 3문항 모두 정답 |
| 2 | 체크 반응 | 체크 버튼을 누른 뒤 카드 숫자와 상단 %가 바뀌기 시작할 때까지의 시간 | 0.1초 이내(서버 응답을 기다리지 않음) |
| 3 | 팀 공유 지연 | 한 사람이 체크한 뒤 다른 팀원 화면에 반영되는 시간 | 평상시 수 초, 연결이 불안정해도 30초 이내(DB 런타임의 주기 새로고침 간격) |
| 4 | 입력 부담 | 팀원이 하루 기록에 쓰는 시간(파일럿 중 3일 표본 측정) | 1인 하루 2분 이내 |
| 5 | 사용률 | 파일럿 10영업일 중 팀원별로 기록이 1건 이상 있는 날 | 팀원 전원 9일 이상 |
| 6 | 기록 정확도 | 사무장이 주 1회 메신저 보고 링크와 업무판 발행 기록을 대조 | 불일치 0건 |
| 7 | 보고서 실용성 | 주간 docx를 회의 자료로 쓰기 전에 손본 시간 | 5분 이내, 사무장 판정 |
| 8 | 문의 집계 | 월말 경로별·유형별 문의 수를 별도 수작업 없이 산출 | 업무판 성과 화면 숫자만으로 산출 가능 |

### 2.2 추천: (1) claude.ai 아티팩트

- 팀원은 이미 원고실 때문에 claude.ai에 로그인해 아티팩트를 씁니다. 새 계정, 새 앱, 새 요금이 없습니다.
- 의뢰인이 요구한 체감 요소(체크 쾌감, 진척률 즉시 반영)를 구현할 수 있는 안은 (1)과 (4)뿐입니다. 그중 (1)은 인증·권한·호스팅이 이미 해결되어 있습니다.
- xlsx·docx를 브라우저에서 바로 만들 수 있어 내보내기에 별도 서버가 필요 없습니다.
- 원고실과 같은 방식(app 폴더의 단일 HTML, Claude Code로 재게시)이라 관리자가 새로 배울 것이 없습니다.

전환 조건: 문의를 입력해야 하는 사람(예: 상담 접수 직원) 중 claude.ai 계정을 만들 수 없는 사람이 있으면 (2) 구글 시트안으로 전환을 검토합니다. 이때 체크 연출은 포기해야 합니다.

### 2.4 원고실과 합칠지, 따로 만들지

따로 만듭니다. 대신 원고실의 구조는 최대한 재사용합니다.

- 합치지 않는 이유
  1. 원고실 HTML은 개인 설치 키트(kit/wonkosil-kit)로 팀원마다 복제됩니다. 업무판을 원고실 안에 넣으면 팀원마다 빈 업무판이 생겨 팀 데이터가 갈라집니다.
  2. 원고실 장애가 업무판까지 번집니다. 원고실은 글 생성용 큰 파일입니다(template.html 893줄).
  3. 권한 규칙이 다릅니다. 업무판은 문의 데이터를 읽기 등급으로 막아야 합니다.
- 재사용하는 것
  1. 디자인 토큰: 원고실 :root 변수 이름과 다크 모드 구조, 글꼴(IBM Plex Sans KR)을 그대로 씁니다.
  2. DB 규칙 패턴: 원고실처럼 '읽기 view, 쓰기 interact, 설정 쓰기 admin'에서 출발합니다.
  3. user 사용법: 원고실의 profiles 호출 방식을 그대로 씁니다.
  4. 운영: app/dashboard.html 한 파일로 만들고 Claude Code로 같은 URL에 재게시합니다. 코퍼스 주입이 없으므로 build.py 단계는 필요 없습니다.
  5. 분야 목록: 원고실의 분야 12개(가사·이혼부터 기타까지)를 문의 분야 선택지로 씁니다.

| 팀장 | 마케팅 팀장(있다면) | 편집자 | 관리자와 같음(권한 방식 A) 또는 관리 화면 제외(권한 방식 B) | 방식 B에서는 관리 화면 |
| 팀원 | 마케팅 담당자(인원 미확인) | 같은 조직이면 참여자, 조직 밖이면 편집자 | 체크, 붙여넣기, 지시 추가, 문의 기록, 내보내기 | 관리 화면(화면에서 숨김) |
| 열람자 | 대표변호사 등(필요 여부 미정) | 뷰어 | 오늘·이번 주·성과 열람 | 문의 상세(DB 규칙으로 차단), 입력 기능 |
| 외부인 | 없음 | 공개 링크 사용 안 함 | 없음 | 전부 |

권한 방식은 의뢰인이 하나를 정합니다.

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 반복 업무·명부·설정 쓰기를 admin 등급으로 둡니다 | 팀장도 관리할 수 있습니다 | 팀원이 조직 밖 편집자라면 팀원도 admin이라 DB 차원에서 막히지 않고 화면에서만 숨깁니다 |
| B | 반복 업무·명부·설정 쓰기를 owner 등급으로 둡니다 | DB 차원에서 소유자 1인만 바꿀 수 있습니다 | 업무판을 사무장 계정으로 게시해야 합니다. 사무장 부재 시 아무도 바꿀 수 없습니다 |

기본 제안은 방식 A에 변경 기록(누가, 언제)을 남기는 것입니다. 소규모 팀에서 기술적 잠금보다 추적이 운영 부담이 적기 때문입니다.

### 4.3 1분 기준을 맞추는 규칙

1. 첫 화면 상단 숫자는 3개만 둡니다: 오늘 %, 이번 주 %, 밀린 일 개수. 문의 수와 월간 %는 각 탭에서 봅니다.
2. 색 의미는 4개로 고정하고 항상 글자를 같이 씁니다: 초록 '끝', 회색 '남음', 빨강 '밀림', 주황 '오래 못 함'. 색만으로 구분하지 않습니다.
3. 화면 용어는 쉬운 말로 바꿉니다.

| 업무 용어 | 화면 표기 |
|---|---|
| 도과 | 밀린 일 |
| 소홀 | 오래 못 함 |
| 진척률 | 끝낸 비율(%) |
| 특별 업무, 회의 지시 | 지시 |
| 업무 템플릿 | 반복 업무 |
| 제외 | 쉬기, 그만하기 |

4. 카드 한 장에는 행동 하나만 둡니다([+]). 수정·삭제는 카드를 길게 누르거나 '…' 메뉴에 넣습니다.
5. 분수와 %를 같은 단위로 셉니다(5.2절). '10개 중 6개'와 '60%'가 항상 일치합니다.
6. 목표가 0인 날(휴무일)은 '0/0' 대신 '오늘은 쉬는 날'로 표시합니다.

### 4.4 디자인 방향(토스 느낌)

- 원고실 토큰의 변수 이름과 다크 모드 구조를 쓰고 값만 조정합니다. 모서리는 원고실 8px에서 카드 16px로 키우고, 큰 숫자는 32~40px 굵게(700) 고정폭 숫자로 씁니다. 그림자 대신 옅은 면 색으로 구분하고 여백을 넓게 둡니다.
- 강조색은 원고실 녹색 계열을 유지합니다. 원고실과 한 식구로 보이고, 다른 회사 브랜드 색을 따라 쓰지 않기 위해서입니다. 대안은 파랑 계열 강조색이며 디자인 검토에서 정합니다.
- 입력은 바텀시트로 띄우고 버튼은 손가락 크기(44px 이상)로 만듭니다. 한 화면에는 메시지 하나만 둡니다.
- 글꼴은 Google Fonts의 IBM Plex Sans KR로 원고실과 같게 둡니다. 외부 스타일시트는 Google Fonts만 쓸 수 있습니다.

## 5. 기능 명세

### 5.1 과업 체계

| 종류 | 화면 표기 | 목표 | 기한 | 누가 만드나 |
|---|---|---|---|---|
| 매일 | 오늘 | 영업일마다 N개 | 그날 24:00 | 관리자(반복 업무) |
| 매주 | 이번 주 | 주마다 N개 | 지정 요일 24:00(기본 금요일) | 관리자 |
| 매월 | 이번 달 | 달마다 N개 | 지정일 24:00(기본 마지막 영업일) | 관리자 |
| 지시 | 지시 | 1개 또는 N개 | 마감일 24:00 | 누구나. 출처를 회의·지시·기타로 표시하고 날짜를 붙입니다 |

- '회의에서 추가된 업무'와 '지시'는 같은 종류(지시)로 묶고 출처 칸으로 구분합니다. 종류를 늘리지 않아 화면 규칙이 단순해집니다.
- 담당은 '팀 공동'(기본, 누구나 체크) 또는 팀원 1명입니다. 공동 업무의 체크는 누른 사람의 기록으로 남습니다.
- 영업일은 월~금에서 관리자가 지정한 휴무일을 뺀 날입니다(가정: 주말 발행 없음). 공휴일 자동 반영은 하지 않고 관리 화면에서 휴무일을 직접 넣습니다.
- 시간 기준은 한국 시간이며, 하루는 00:00에 바뀝니다.

### 5.2 진척 표시

기호 정의
- T(업무, 날짜): 그날 목표 수량입니다. 매일 업무는 영업일이면 일 목표이고, 휴무일이거나 '오늘 건너뛰기'로 지정됐으면 0입니다.
- C(업무, 날짜): 그날 몫으로 기록된 완료 수입니다. 기록마다 '몫 날짜'가 있고, 밀린 날 몫을 나중에 채우면 그 날짜로 셉니다.

| 표시 | 산식 |
|---|---|
| 카드 분수 | 매일 업무: C(업무, 오늘) / T(업무, 오늘). 매주: 이번 주 C 합 / 주 목표. 매월: 이번 달 C 합 / 월 목표. 지시: 완료 수 / 수량 |
| 오늘 % | 매일 업무 전체의 min(C, T) 합 ÷ T 합(오늘분) |
| 이번 주 % | 분자는 매일 업무의 이번 주 영업일별 min(C, T) 합, 매주 업무의 min(주 C, 주 T) 합, 이번 주 마감이거나 밀린 지시의 min(완료, 수량) 합을 더한 값입니다. 분모는 각 목표의 합입니다. 분모에는 아직 오지 않은 요일의 목표도 들어갑니다 |
| 이번 달 % | 같은 방식으로 이번 달 전체를 셉니다(성과 화면에서 표시) |

- 1편, 1건, 1회를 모두 1개로 셉니다. 요청 예시의 '1/14' 표기와 맞습니다.
- 초과분은 %에 넣지 않고 카드에 '+1'로 따로 표시합니다. 한 업무를 많이 한 것이 다른 업무의 부족을 가리지 않게 하기 위해서입니다.
- 백분율은 내림 정수로 표시하고, 모두 끝났을 때만 100%가 됩니다. 99.6%가 100%로 보이는 것을 막습니다.
- 매월 업무를 체크해도 상단 두 숫자는 움직이지 않습니다. 카드 자체의 연출로 반응을 보여 줍니다(5.5절). 매월 업무를 이번 주 %에 나눠 넣는 안은 산식이 어려워져 1분 기준에 맞지 않아 기각했습니다.
- 대안으로 업무별 동일 가중 평균(업무마다 달성률을 구해 평균)을 검토했습니다. 분수 합계와 %가 어긋나 기각했습니다.

### 5.3 밀림(도과)·오래 못 함(소홀) 판정

#### 밀림

| 종류 | 판정 시점 | 밀린 수량 | 해소 | 주·달이 바뀌면 |
|---|---|---|---|---|
| 매일 | 다음 날 00:00 | 이번 주의 지난 영업일 d마다 max(0, T(d) − C(d)) | 밀린 카드의 [+]를 누르면 그날 몫으로 기록됩니다. 오늘 몫을 다 채운 뒤 더 한 것과 붙여넣기 초과분은 이번 주에서 가장 오래된 부족분을 자동으로 채웁니다 | 이월하지 않습니다. 성과에 '지난주 미달'로 남습니다 |
| 매주 | 지정 요일 다음 날 00:00 | max(0, 주 T − 주 C) | 같은 주 안에서 체크하면 해소됩니다 | 이월하지 않고 미달로 기록합니다 |
| 매월 | 지정일 다음 날 00:00 | max(0, 월 T − 월 C) | 같은 달 안에서 체크하면 해소됩니다 | 이월하지 않고 미달로 기록합니다 |
| 지시 | 마감일 다음 날 00:00 | 수량 − 완료 | 완료하거나 관리자가 '취소'하면 해소됩니다 | 끝날 때까지 계속 밀린 일로 남고 'D+일수'를 표시합니다 |

- 반복 업무를 이월하지 않는 이유: 주마다 새로 시작해야 부담이 쌓이지 않고 주간 보고가 깔끔하게 닫힙니다. 미달은 지워지지 않고 성과와 '오래 못 함' 판정에 남습니다.
- 기록은 '몫 날짜' 기준입니다. 어제 한 일을 오늘 기록해도 어제 몫이 됩니다. 기록 시각이 몫 날짜보다 하루 이상 늦으면 '늦게 기록' 표시를 남깁니다. 지난 7일 이내만 팀원이 기록할 수 있고, 그보다 이전은 관리자만 기록합니다.

#### 오래 못 함(반복 업무에만 적용)

아래 두 조건 중 하나라도 맞으면 '오래 못 함'입니다.

1. 공백: G는 마지막 완료 몫 날짜 이후 목표가 있었던 영업일 수입니다. 매일 업무는 G가 3 이상, 매주 업무는 10 이상, 매월 업무는 25 이상이면 해당합니다.
2. 저조: R은 직전 4주(이번 주 제외) 동안 주마다 min(C, T)를 합한 값 ÷ T를 합한 값입니다. 매월 업무는 직전 3개월을 봅니다. R이 50% 미만이면 해당합니다.

- 판정하지 않는 경우: 업무를 시작한 지 1주 미만(매월 업무는 1개월 미만)인 경우, 쉬기 기간, 휴무일, 건너뛴 날입니다. 쉬기 기간과 휴무일은 G와 R 계산에서도 뺍니다.
- 표시: 카드에 '오래 못 함' 배지를 답니다. 이번 주 화면 목록에는 '마지막 10/14 · 9영업일째', '최근 4주 38%'처럼 근거 숫자를 함께 보여 줍니다. 정렬은 G를 허용 공백으로 나눈 값이 큰 순입니다.
- 밀림과 따로 두는 이유: 밀림은 매주 초기화되므로 주를 넘어 반복되는 미달을 잡지 못합니다. 오래 못 함이 그 빈틈을 메웁니다.
- 기준값(3·10·25영업일, 50%, 4주)은 가정치입니다. 관리 화면에서 바꿀 수 있고 파일럿 결과로 조정합니다.

### 5.4 업무 추가·제외·계획

| 기능 | 누가 | 내용 |
|---|---|---|
| 반복 업무 추가 | 관리자 | 이름, 채널, 주기, 목표 수량, 단위(편·건·회), 기한 요일·일, 담당, 시작일을 넣습니다 |
| 목표 변경 | 관리자 | 적용 시작일(기본 다음 주 월요일)을 정해 목표 이력에 쌓습니다. 지난 기간의 진척률은 그때 목표로 계산되어 바뀌지 않습니다 |
| 쉬기 | 관리자 | 기간을 정해 일시 제외합니다. 그 기간에는 목표가 0이고 오래 못 함 판정도 하지 않습니다 |
| 그만하기 | 관리자 | 종료일 이후 계산에서 뺍니다. 기록은 보존하고, 기록이 0건일 때만 완전 삭제할 수 있습니다 |
| 오늘 건너뛰기 | 누구나, 사유 필수 | 특정 날의 특정 업무 목표를 0으로 만듭니다(예: 외근, 시스템 장애). 사유와 기록자가 성과 화면에 남습니다. 거짓 밀림 표시를 막기 위한 장치입니다 |
| 지시 추가 | 누구나 | 내용, 출처(회의·지시·기타)와 날짜, 담당, 수량, 마감일을 넣습니다 |
| 지시 취소 | 관리자 | 상태만 '취소'로 바꾸고 기록은 남깁니다 |
| 다음 주 계획 | 관리자 | 이번 주 화면에서 다음 주로 이동해 반복 목표, 지시 마감, 휴무일을 미리 보고 조정합니다. '이번 주 중점'을 1~3줄 메모로 남기면 오늘 화면 상단에 한 줄로 보입니다 |

'미진한 부분 파악'은 따로 화면을 만들지 않습니다. 이번 주 화면의 업무별 달성률 낮은 순 정렬, 밀린 일 목록, 오래 못 함 목록 세 가지로 해결합니다.

### 5.5 체크 피드백(완료 쾌감)

| 순간 | 연출 | 길이 |
|---|---|---|
| [+]를 누름 | 서버 응답을 기다리지 않고 바로 반영합니다. 버튼이 눌렸다 튀어 오르고, 카드 분수가 1/2에서 2/2로 바뀌며, 카드 막대가 차오릅니다. 상단 %는 숫자가 굴러 올라갑니다 | 200~400ms |
| 업무 하나의 목표 도달 | 카드가 초록으로 바뀌고 '끝' 표시와 짧은 문구('로톡 오늘 몫 끝')가 나온 뒤 '끝낸 일'로 내려갑니다 | 약 600ms |
| 오늘 100% | 화면 위에서 색종이가 1.5초 떨어지고 '오늘 할 일 다 끝냈습니다' 문구가 나옵니다. 사람별로 하루 1회만 나옵니다(기기 저장) | 1.5초 |
| 이번 주 100% | 색종이를 더 크게 띄우고 주간 달성 문구를 보여 줍니다. 사람별로 주 1회만 나옵니다 | 2초 |
| 붙여넣기 반영 | 업무별 체크 연출이 순서대로 재생됩니다 | 업무당 약 300ms |
| 진동 | 지원하는 휴대폰에서만 짧게 울리고, 미지원 기기에서는 생략합니다 | 10ms |

- 되돌리기: 체크 직후 5초 동안 '되돌리기' 알림을 띄웁니다. 그 뒤에는 카드 메뉴의 '하나 빼기'로 되돌립니다.
- 저장 실패: 숫자를 원래대로 돌리고 '저장 안 됨, 다시 눌러 주세요'를 표시합니다.
- 움직임 줄이기 설정을 켠 기기에서는 애니메이션 없이 숫자만 바꿉니다.
- 소리는 사무실 환경을 고려해 MVP에서 뺍니다(8절).

### 5.6 발행 보고 붙여넣기(자동 체크)

현재 팀원은 날짜, 꺾쇠 괄호로 감싼 채널명(〈로톡〉, 〈티스토리〉, 〈블로그〉), 링크, 제목을 메신저에 올립니다(캡처 확인). 이 텍스트를 그대로 붙여넣으면 다음 순서로 처리합니다.

1. 날짜 읽기: 첫 'M/D' 표기(예: 10/26)를 올해 날짜로 읽습니다. 없으면 오늘로 잡고, 확인 화면에서 바꿀 수 있습니다.
2. 링크 뽑기: http로 시작하는 주소를 모두 찾습니다.
3. 업무 판별: 관리 화면의 '링크 판별표'를 위에서부터 대조합니다.

| 주소 조건 | 제목 조건 | 업무(초안) |
|---|---|---|
| lawtalk.co.kr | 없음 | 로톡 글 |
| tistory.com으로 끝남 | 없음 | 티스토리 정보글 |
| blog.naver.com/jinnsollaw | '성공사례' 포함 | 블로그 성공사례 |
| blog.naver.com/jinnsollaw | 그 외 | 블로그 정보글(jinnsollaw) |
| blog.naver.com/jinnsol-law | '성공사례' 포함 | 블로그 성공사례 |
| blog.naver.com/jinnsol-law | 그 외 | 블로그 정보글(jinnsol-law) |
| 위에 없는 주소 | 바로 위 꺾쇠 채널명 | 채널명으로 추정하고 확인 화면에서 '확인 필요'로 표시 |
| 짧은 주소(naver.me 등) | 없음 | 분류 안 됨. 사용자가 업무를 고릅니다 |

4. 제목 읽기: 링크와 같은 줄의 나머지 글자를 제목으로 씁니다. 없으면 바로 윗줄을 씁니다.
5. 중복 확인: 이미 기록된 주소는 '이미 기록됨'으로 빼 둡니다.
6. 확인 시트: '10/26(월) 기록: 로톡 2 · 티스토리 2 · 블로그 2(성공사례 1)'처럼 보여 주고 [넣기] 한 번으로 반영합니다. 업무별 체크 연출이 재생됩니다.

- 오늘 몫을 넘는 분량은 이번 주에서 가장 오래된 부족분을 채웁니다(5.3절).
- 판별표는 관리자가 고칩니다. 형사·민사·기업 블로그 구분처럼 계정이 늘면 줄을 추가합니다.
- 반대 방향 기능도 둡니다. 성과 화면의 '메신저용 요약 복사'가 같은 형식의 텍스트를 만들어 주므로, 업무판에서 먼저 체크한 사람은 그 텍스트를 단체방에 붙이면 됩니다(5.9절).

### 5.7 문의 기록과 추적

기록 바텀시트는 버튼 위주로 만들어 10초 안에 끝나게 합니다.

| 순서 | 항목 | 입력 방식 | 필수 |
|---|---|---|---|
| 1 | 유형 | 전화 · 방문 · 예약 큰 버튼 3개 | 예 |
| 2 | 유입 경로 | 버튼 목록: 네이버 블로그, 네이버플레이스, 네이버 검색(기타), 로톡, 티스토리·구글, 홈페이지, 기사·칼럼, 쇼츠, 지인 소개, 기존 의뢰인, 모름. 목록은 관리자가 편집합니다(가정 목록) | 예 |
| 3 | 검색어 | 짧은 글 입력, '모름' 버튼 | 아니요 |
| 4 | 본 글 | 짧은 글 입력(제목 일부나 주소) | 아니요 |
| 5 | 분야 | 원고실 분야 12개 버튼 | 아니요 |
| 6 | 일시 | 기본값은 지금이고 바꿀 수 있습니다 | 자동 |
| 7 | 메모 | 200자 이내 | 아니요 |

- 전화를 받는 사람에게 묻는 문장 예시를 시트 상단에 둡니다: '어떻게 알고 연락 주셨어요? 무엇을 검색하셨어요?'
- 후속 체크는 문의 목록에서 한 번 눌러 바꿉니다.
  - 리뷰: 대상 아님, 요청 전, 요청함(날짜 자동), 작성 확인. 방문·예약은 '요청 전', 전화는 '대상 아님'으로 시작합니다(가정: 리뷰는 실제로 만난 사람에게 요청). 바꿀 수 있습니다.
  - 다시 연락: 없음, 필요, 완료.
- 오늘 화면 연결: '요청 전' 문의가 있으면 오늘 화면에 '리뷰 요청할 문의 N건' 카드가 나타납니다. 누르면 문의 목록으로 갑니다.
- 집계(문의 탭 상단, 주·월 전환)
  - 유형별 건수(전화·방문·예약)
  - 경로×유형 교차표
  - 검색어 상위 10개(앞뒤 공백·중복 공백을 정리한 뒤 빈도 순)
  - 분야별 건수
  - 리뷰 요청률: (요청함 + 작성 확인) ÷ (대상 아님을 뺀 전체)
  - 리뷰 작성 확인 수, 다시 연락 '필요' 남은 수
  - 전주·전월 대비 증감

### 5.8 개인정보 보호

1. 수집하지 않는 것: 이름, 전화번호, 주소, 주민등록번호, 사건 내용 상세. 연락처는 업무판에 두지 않고 기존에 쓰는 상담 기록에서 확인합니다. 기존 기록 수단이 무엇인지는 열린 질문입니다.
2. 메모·검색어·본 글 칸에 휴대전화 번호 형태(010으로 시작하는 숫자열)나 주민등록번호 형태가 들어가면 저장을 막고 이유를 표시합니다. 이름은 자동으로 거를 수 없으므로 입력 칸에 '이름·연락처를 쓰지 마세요' 안내를 고정합니다.
3. 문의 컬렉션은 DB 규칙으로 읽기 등급을 참여자(interact) 이상으로 올립니다. 뷰어와 외부 열람자는 문의 상세를 읽을 수 없습니다. 집계 숫자를 열람자에게 보여 줄지는 열린 질문입니다.
4. 공개 링크로 공유하지 않습니다. 원고실 설치 키트의 금지 원칙과 같습니다.
5. 내보낸 엑셀·워드에도 식별정보가 없습니다. 위 1과 2로 원천 차단되기 때문입니다.
6. 팀원 정보는 명부의 호칭과 역할만 저장합니다. claude.ai 프로필 이름은 저장하지 않고 화면에 그릴 때만 불러옵니다(런타임 지침).
7. 팀원별 실적 공개 범위(팀원끼리 서로 보는지)는 의뢰인이 정합니다. 기본값은 성과 화면에만 팀원별 완료 수를 표시하는 것입니다.

### 5.9 일·주·월 성과 공유

성과 탭 상단에서 일·주·월을 전환합니다. 지난 기간으로 이동할 수 있습니다.

| 묶음 | 내용 |
|---|---|
| 큰 숫자 3개 | 팀 끝낸 비율, 발행 수, 문의 수. 각각 전 기간 대비 증감을 함께 표시합니다 |
| 업무별 표 | 업무, 목표, 완료, 달성률, 미달 수량. 달성률 낮은 순으로 놓습니다 |
| 발행 목록 | 채널별 제목·링크와 성공사례·정보글 수 |
| 문의 요약 | 5.7절 집계의 축약판 |
| 밀림·오래 못 함·건너뛰기 | 업무, 날짜, 사유 |
| 지시 처리 | 기간 안에 마감인 지시의 완료·밀림·취소 |
| 팀원별 기여 | 팀원별 완료 수(표시 여부는 설정) |
| 메모 | 이번 주 중점, 사무장 주간 메모 |

- 실시간 공유: 모든 화면은 공용 DB를 구독하므로 누가 체크하면 다른 사람 화면도 바로 바뀝니다. 카드에는 체크한 사람의 이니셜을 작게 표시합니다.
- 메신저용 요약 복사: 오늘·이번 주·이번 달 요약을 지금 단체방 보고 형식(날짜, 채널별 링크와 제목)에 진척 %와 밀린 일을 더한 텍스트로 만들어 클립보드에 넣습니다. 업무판에 들어오지 않는 사람과도 공유할 수 있습니다.

### 5.10 내보내기

성과 탭의 [엑셀 저장]과 [워드 저장]으로 내보냅니다. 기간은 이번 주, 지난주, 이번 달, 지난달, 직접 지정 중에서 고릅니다. 라이브러리(SheetJS, docx)는 버튼을 누를 때 불러와 첫 화면 속도에 영향을 주지 않게 합니다. 파일명은 팀 관행인 '2026.10.27.-제목' 형식을 따릅니다.

엑셀(xlsx), 파일명 예: 2026.10.27.-마케팅 업무기록(2026.10.26.~11.1.).xlsx

| 시트 | 열 | 용도 |
|---|---|---|
| 요약 | 기간, 팀 끝낸 비율, 업무별 목표·완료·달성률·미달, 밀림·오래 못 함 목록 | 한눈 보기 |
| 업무기록 | 몫 날짜, 기록 시각, 팀원, 업무, 수량, 제목, 링크, 늦게 기록 여부 | 원장(가공용) |
| 발행목록 | date, channel, title, main_kw(빈칸), url | data/published.csv와 같은 열이라 그대로 옮길 수 있습니다 |
| 문의 | 일시, 유형, 경로, 검색어, 본 글, 분야, 리뷰 상태, 다시 연락 | 문의 원장(식별정보 없음) |
| 문의집계 | 경로×유형 교차표, 검색어 상위 20, 분야별 | 월간 분석 |
| 지시 | 등록일, 출처, 내용, 담당, 수량, 마감, 완료일, 상태 | 회의 지시 추적 |
| 건너뛰기 | 날짜, 업무, 사유, 기록자 | 목표 조정 근거 |

관리 화면에는 '전체 백업(xlsx)'을 따로 둡니다. 전 기간의 위 시트에 반복 업무 정의와 목표 이력 시트를 더한 파일입니다. 연 1회와 플랫폼 변경 전에 받습니다.

워드(docx), 파일명 예: 2026.11.01.-마케팅 주간보고.docx(월간은 '월간보고')

1. 제목과 기간
2. 한 줄 요약: 팀 끝낸 비율, 전주 대비, 발행 수, 문의 수
3. 업무 달성 표: 업무, 목표, 완료, 달성률
4. 밀린 일과 오래 못 한 일, 건너뛴 날과 사유
5. 발행 목록: 채널별 제목과 링크
6. 문의 집계: 유형별, 경로별, 검색어 상위 10, 리뷰 요청률
7. 지시·회의 업무 처리 현황
8. 다음 주 계획(지시 마감, 목표 변경, 휴무일)과 사무장 메모

- 워드에는 차트를 넣지 않고 표로만 구성합니다(2단계 사유는 8절).
- 다운로드는 저장 확인 창이 뜨며, 사용자가 거절하면 저장되지 않습니다. 저장 기능을 쓸 수 없는 화면에서는 버튼을 숨깁니다.

## 6. 데이터 모델 초안

업무판 아티팩트 DB 하나에 아래 컬렉션을 둡니다. 필드 이름은 원고실과 같은 camelCase를 씁니다.

| 경로 | 문서 단위 | 주요 필드 | 쓰기 | 연간 문서 수(가정) |
|---|---|---|---|---|
| `config/main` | 1개 | workDays(월~금), holidays(날짜 목록), neglect(dailyGap 3, weeklyGap 10, monthlyGap 25, lowRate 0.5, windowWeeks 4), linkRules(주소·제목 조건 → 업무 id, 순서 있음), inquiryPaths(경로 목록), fields(분야 목록), showMemberStats, updatedAt, updatedBy | 관리 | 1 |
| `members/{memberId}` | 팀원 1명 | name(팀 내 호칭), role(lead 또는 member), active, order, userId(있으면) | 관리 | 10 미만 |

설계 근거
- 완료 여부는 따로 저장하지 않고 logs의 entries에서 계산합니다. 지시의 완료도 entries로 셉니다. 여러 사람이 한 문서의 숫자를 올리면 마지막 쓰기만 남는 문제가 있어 이를 피하기 위해서입니다.
- 팀원별 하루 문서 1개 구조는 각자 자기 문서에만 씁니다. 동시 쓰기 충돌이 없고 문서 수가 작습니다. 연 약 2,700개로 상한 25,000개까지 9년 이상 여유가 있습니다.
- 같은 사람이 두 기기에서 동시에 체크하면 한쪽 기록이 덮일 수 있습니다. 화면이 늘 최신 문서를 구독한 상태에서 쓰고 연속 체크는 묶어서 한 번에 저장해 위험을 줄입니다. 남는 위험은 파일럿에서 확인합니다.
- 목표 이력(targets)을 두는 이유는 목표를 바꿔도 지난 기간 진척률이 그대로 유지되게 하기 위해서입니다.
- 주소 중복 확인은 urls 목록에 array-contains 조회로 합니다.
- 화면을 열 때 읽는 범위: 설정, 명부, 반복 업무, 열린 지시, 최근 6주 logs(팀원 5명 기준 약 150문서). 구독 수는 10개 미만으로 상한 64개보다 훨씬 적습니다. 문의는 문의 탭을 열 때 이번 달 것만 읽습니다.
- 신원: 처음 접속하면 팀 명부에서 '나'를 고르고 기기에 기억합니다. 기록에는 memberId와, 있으면 claude.ai userId를 함께 남겨 사후 확인에 씁니다.
- 초기 데이터: 반복 업무와 명부는 페이지 코드에 넣지 않습니다. 게시 후 Claude Code 세션이 ArtifactData로 7절 확정본을 넣거나 관리자가 관리 화면에서 입력합니다. DB가 비어 있으면 '반복 업무가 아직 없습니다' 안내를 보여 줍니다.

선언할 런타임 기능(권한 방식 A 기준)

```json
{
  "db": {"rules": [
    {"path": "", "read": "view", "write": "interact"},
    {"path": "config", "write": "admin"},
    {"path": "members", "write": "admin"},
    {"path": "tasks", "write": "admin"},
    {"path": "weeks", "write": "admin"},
    {"path": "inquiries", "read": "interact", "write": "interact"}
  ]},
  "user": {"scopes": ["profile"]},
  "downloads": true
}
```

권한 방식 B를 고르면 config, members, tasks, weeks의 write를 owner로 바꿉니다. sample, mcp, room은 MVP에서 선언하지 않습니다.

## 9. 열린 질문(의뢰인 결정 사항)

1. 팀 인원과 명부: 몇 명이며 화면에 어떤 호칭으로 표시할지 정해 주십시오.
2. 초대 방식과 관리 권한: 팀원이 같은 claude.ai 조직 구성원인지, 외부 이메일 초대인지 알려 주십시오. 관리 권한은 3절 방식 A(팀장도 관리)와 B(소유자 1인만 관리) 중에서 고릅니다. 방식 B라면 업무판을 사무장 계정으로 게시해야 합니다.
3. 업무 수량과 완료 기준: 7절 표의 '확인할 것' 칸 전부를 정해 주십시오. 특히 '성공사례'(6번), 리뷰 작업, 로톡 작업, 네이버플레이스 작업은 무엇을 하면 1회인지 정해야 합니다.
4. 블로그 계정 구성: jinnsollaw, jinnsol-law와 형사·민사·기업 블로그의 관계와 계정별 하루 목표를 알려 주십시오.
5. 쇼츠 게시 플랫폼: 링크 판별에 필요합니다.
6. 영업일: 주말·공휴일 발행 여부와 하루 마감 시각(기본 24:00)을 정해 주십시오.
7. 문의 기록 담당: 전화·방문을 받는 사람이 마케팅팀 밖에 있다면 그 사람도 업무판 계정(참여자 이상)이 필요합니다. 연락처를 확인할 기존 상담 기록 수단도 알려 주십시오.
8. 외부 열람자: 대표변호사 등에게 열람을 줄지, 준다면 문의 집계 숫자까지 보여 줄지 정해 주십시오.
9. 팀원별 실적 공개: 팀원끼리 서로의 완료 수를 보게 할지(기본안: 성과 화면에만 표시) 정해 주십시오.
10. 메신저 보고 유지: 파일럿 후에도 단체방 보고를 계속할지, 업무판의 '메신저용 요약 복사'로 대체할지 정해 주십시오.
