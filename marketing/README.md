# 마케팅 노출 측정(프로토타입)

목적: 진앤솔의 검색 노출을 비교군과 같은 기준으로 재고, 우리가 밀리는 키워드와 그 관측 근거(약점 목록)를 뽑는다. 점수는 추세를 보는 계기판이고, 핵심 산출물은 약점 목록과 다음 과제 후보다.

실행 방식: 정기 자동 실행 없음. 사무장님이 필요할 때 윈도우 PC에서 크롬을 켜고 돌린다. 한 번 측정에 키워드 31개와 핵심 키워드 재측정 8개 기준 약 30~40분이 걸린다(요청 사이 4~8초 대기).
- 다른 PC(집 등)에서 돌려도 된다. 플레이스 목록은 설정 좌표 기준이라 장소와 무관하다. 구글은 접속 회선 위치의 영향을 받을 수 있어, 측정 PC가 직전 회차와 다르면 리포트 첫머리에 주의가 나온다

## 1회 설치(사무실 PC)
1. 파이썬 설치: python.org에서 3.12 이상, 설치 첫 화면에서 "Add python.exe to PATH" 체크
2. 명령 프롬프트에서 `py -m pip install playwright` (크롬을 그대로 쓰므로 `playwright install`은 하지 않아도 된다)
3. 이 저장소를 PC에 받는다(GitHub Desktop 권장. 측정 결과를 올려 클라우드 세션에서 리포트를 받을 수 있다)
4. AI 검색 측정을 Claude가 하게 하려면 Claude 데스크톱 앱과 크롬 확장 Claude in Chrome을 설치한다(없으면 수동 붙여넣기)

## 처음 한 번 채울 설정
- `config/entities.json`
  - us.place_ids: 우리 네이버 플레이스 번호(플레이스 주소 m.place.naver.com/place/숫자 의 숫자)
  - us.phones: 사무소 전화번호(AI 답변 정보 오류 점검용)
  - us.domains: 홈페이지 도메인 추가
  - competitors: 비교 업체. 리포트 11번 '비교군 후보'에서 골라 `{"key": "표시명", "names": ["상호 일부"], "place_ids": ["번호"], "blog_ids": ["블로그 아이디"]}` 형식으로 넣는다. blog_ids를 비워도 블로그 이름에 상호가 들어 있으면 그 업체 블로그로 센다. 리포트 첫머리 '비교군 블로그' 줄에 못 찾은 업체가 나오고, 11번 아래에 등록 후보 블로그가 나온다
  - network_firms: 비교에서 뺄 네트워크펌 상호(현재 대륜). 추가할 곳이 있으면 넣는다
- `config/keywords.csv`: 키워드 31개(분야별 지수를 위해 가사·행정 보강). priority(분야 우선순위, 기본 1)와 volume(네이버 검색광고 키워드 도구의 월간 검색수)을 채우면 가중치에 반영된다. 비어 있으면 같은 가중치
- `config/collect.json`: office.lat, office.lng에 사무실 좌표(네이버 지도에서 확인)
  - regions: 지역 키워드(keywords.csv의 region)의 플레이스 목록 기준 좌표. 현재 마산(창원지법 마산지원 인근 법률사무소 밀집지), 진해(석동로). 값은 2026-11-01 플레이스 수집 데이터의 업체 좌표에서 잡았다. 없는 지역은 사무실 좌표
  - repeat_keywords: 같은 날 한 번 더 재는 핵심 키워드(흔들림 폭 측정). 비우면 재측정을 하지 않는다
  - ai_rounds: AI 질문당 회차(기본 1). 2로 올리면 언급률 오차 범위가 좁아지지만 AI 수집 시간이 그만큼 늘어난다
- `config/ai_prompts.csv`: AI에 던질 고정 질문 8개

## 원클릭(권장)
저장소 맨 위 `원클릭리포트.bat` 더블클릭 한 번으로 준비 → 최신 코드 받기 → 검색 수집 → AI 답변 수집 → 리포트(docx 자동 열림) → 결과 올리기까지 진행한다(약 1시간 20분). 사람 손은 보안문자가 뜰 때만 필요하다. 바탕화면 바로가기: 파일 우클릭 → 보내기 → 바탕 화면에 바로 가기 만들기.
- AI 수집은 Claude Code(`claude`)와 Claude in Chrome 연결이 되어 있어야 한다(AI_PROTOCOL.md). 없으면 건너뛰고 나머지는 진행
- 자동 올리기는 git이 있어야 한다(Git for Windows 권장, 처음 한 번 GitHub 로그인). 올리기가 거부되면 최신 내용을 합쳐 한 번 더 시도한다
- 수집이 기준(scoring.json의 min_channel_coverage, 키워드 70%)에 못 미치면 리포트만 만들고 올리지 않는다. 그래도 올리려면 `py tools\mkt_all.py --push-anyway`
- 중간에 끊겨도 다시 실행하면 끝난 부분은 건너뛴다

## 측정할 때마다(수동 단계별)
1. 상담 입력: `data/consults_local.csv`를 엑셀로 열어 지난 측정 이후 상담을 한 줄씩 넣는다. 이 파일은 이 PC에만 남고 저장소에 올라가지 않는다. 없으면 리포트를 처음 만들 때 양식이 생긴다. 예전 위치 `data/consults.csv`에 넣은 행은 리포트를 만들 때 이 파일로 옮겨진다
   - date: 2026-10-27 형식
   - channel: 네이버블로그, 플레이스, 파워링크, 로톡, 구글, AI, 홈페이지, 소개, 기타 중 하나
   - area: 형사, 민사, 가사, 행정 / region: 창원, 마산, 진해, 김해 등 / retained: Y 또는 N
   - 엑셀 기본 저장 형식도 읽는다. 날짜를 못 읽은 행은 상담 요약에 건수로 나온다
   - 요약은 리포트에 넣지 않고 `output/local/<날짜>_상담요약.txt`에 따로 남는다(리포트는 저장소에 올라간다)
2. `marketing\측정.bat` 실행: 측정 전용 크롬 창이 뜨고 네이버 통합검색, 플레이스 목록, 구글, 발행 글 누락 점검 순으로 돈다. 보안문자가 뜨면 창에서 풀고 검은 창에서 Enter. 끊겨도 다시 실행하면 이어서 한다
3. AI 검색 답변 수집: `AI_PROTOCOL.md` 절차(Claude에게 시키거나 수동 붙여넣기)
4. `marketing\리포트.bat` 실행 → `output/marketing/<날짜>_리포트.txt`, `<날짜>_키워드표.csv`, `<날짜>_리포트.docx`(보고용. python-docx가 없으면 건너뛴다: `py -m pip install python-docx`)
5. (선택) 결과를 GitHub에 올리고 클라우드 세션에 "마케팅 리포트 분석해줘"라고 하면 편집장이 리포트를 읽고 과제를 정리한다

## 점수 산식(config/scoring.json)
- 순위 점수(rank_curve): 1위 10점에서 한 계단마다 15%씩 줄어 30위까지 준다(2위 8.5, 3위 7.2, 5위 5.2, 10위 2.3, 18위 0.6, 30위 0.1). 10위 밖 변동도 점수에 나타난다. 업계 클릭률이 아니라 자체 설정값이며 비교 일관성을 위한 것이다. rank_curve를 지우면 예전 계단식(rank_points)으로 돌아간다
- 채널 점수 = Σ(키워드 가중치 × 순위 점수) ÷ Σ(키워드 가중치 × 10) × 100
  - 네이버 콘텐츠: 통합검색 안 블로그·카페·지식인·로톡·웹문서·뉴스·동영상의 화면 순서. 같은 블로그 글이 3건 이상 연달아 나오는 채널 카드는 결과 1건으로 센다
  - 네이버 플레이스: 플레이스 목록의 광고 제외 순위(목록 수집 실패 시 통합검색 플레이스 영역 순서). 측정 좌표가 다른 회차끼리는 비교하지 않는다
  - 구글: 자연검색 결과 순서. 주인을 알 수 없는 네이버 블로그 결과도 순위 칸은 차지한다
  - 구글 지도: 구글 화면의 '웹사이트' 버튼이 달린 지도 결과 순서('방문' 미리보기 창은 뺀다)
  - AI 검색: 등록 업체 중 답변에서 처음 언급된 순서(1번째 10, 2번째 8 ...), 언급률은 따로 표시. 내용이 없거나 로그인·오류 안내문인 파일은 분모에서 뺀다
- 종합지수 = 네이버 35, 플레이스 25, 구글 10, 구글 지도 5, AI 15 가중 평균(측정 안 된 채널은 빼고 환산)
- 수집이 기준에 못 미친 채널은 0점이 아니라 미측정으로 뺀다(검색 채널 키워드 70%, AI 답변 50%)
- 변동값(괄호)은 두 회차를 현재 설정으로 다시 계산하고, 두 회차 모두 측정된 같은 키워드·같은 답변만 비교한다. 겹치는 범위가 70%보다 좁으면 표시하지 않는다
- 파워링크는 유료 광고라 점수에 넣지 않고 노출 키워드 수만 표시

## 세부 지표와 신뢰도(리포트 3~5, 9~10번)
- 세부 지표: 채널마다 우리와 그 채널 1위 업체의 상위 3위·상위 10위·노출 키워드 수, 노출 시 평균 순위
- 분야·지역별 지수: 그 분야(keywords.csv area)·지역(region) 키워드만으로 다시 계산. 분야에는 같은 분야 AI 질문 포함. 키워드 3개 미만 그룹은 크게 흔들린다
- 오차 범위: 측정 키워드·답변을 복원 추출로 bootstrap(300)회 다시 뽑아 계산한 우리 지수·순위의 90% 범위
- 직전 대비 판정: 두 회차 공통 키워드·답변을 같은 방식으로 다시 뽑아 변동의 90% 범위를 내고, 범위가 0을 포함하면 '변화 판단 불가(오차 범위 안)'
- 같은 날 재측정: repeat_keywords를 다른 단계가 끝난 뒤 한 번 더 수집해 노출 여부 일치율과 평균 순위 차이를 낸다. 순위 변동(7번)은 이 흔들림의 2배 이상(최소 3계단)만 적는다
- AI 언급률 95% 범위: 답변 수가 적어 생기는 오차(윌슨 방식). 답변 24건에 2건 언급이면 2.3~25.8%
- 네이버 콘텐츠 주인 구성: 상위 10건 중 등록 업체, 미등록 법률 블로그(블로그명에 변호사·법률·법무·로펌·law), 주인 미상 등. 미등록 법률 블로그가 40%(law_blog_alert) 이상인 키워드는 비교를 참고용으로 표시
- 플레이스 요인(9번): 키워드마다 순위와 지표(방문자리뷰, 블로그리뷰, 사진, 업체명 속 키워드 단어, 거리)의 스피어만 상관을 구해 업체 수로 가중 평균. 업체 8곳 미만 키워드는 뺀다
- 콘텐츠 최근성(10번): 상위 10위 안 글의 요약문 게시 시점("3일 전", "2026.07.20.")으로 최근 30일(fresh_days) 글 비율과 업체별 상위 노출 글 수

## 시범 측정(2026-10-23, 키워드 3개)으로 확인·수정한 것
- 네이버 통합검색: 플레이스·블로그·카페·웹문서·파워링크(ader.naver.com) 분류 정상
- 플레이스 목록: 자연 순위(placeList)와 광고(adBusinesses)가 별도 묶음임을 확인해 분리. 방문자리뷰·평점·사진 수·예약·톡톡·쿠폰 수집. 블로그리뷰 수는 목록 데이터에서 모두 0으로 나와 쓰지 않음
- 구글 모바일: 자연검색 링크가 암호화돼 있어 화면에 보이는 주소로 분류. '웹 검색결과' 앞의 광고와 지도 결과를 분리
- 우리 플레이스 번호·전화·홈페이지(jinnsol.co.kr)와 사무실 좌표는 수집된 네이버 데이터에서 채움. 홈페이지 도메인이 맞는지 확인 필요
- 시범 결과는 `data/measure/_pilot-2026-10-23/`에 보관(리포트 비교 대상에서 제외)
- 분류 규칙을 고치면 `py tools\mkt_collect.py --reparse <날짜>`로 브라우저 없이 저장된 원본을 다시 분석한다. tools/mkt_common.py의 PARSER_VERSION을 올리면 리포트가 비교 회차까지 자동으로 다시 분석한다
- 시험: `py -m unittest discover -s tools -p "test_mkt.py"`(브라우저·네트워크 없음, 저장 원본을 고정 입력으로도 쓴다)

## 한계
- 네이버 순위 산정 방식은 비공개다. 9번 상관 분석은 추정이고 인과가 아니며, 4주 이상 쌓여야 읽을 만하다. 업체명 키워드는 관측 요인일 뿐이며 '전문' 표시 등은 광고 규정 검토가 먼저다
- 플레이스 측정 기준점은 사무실과 regions의 지역 좌표뿐이다. 그 밖 위치 사용자의 순위는 다를 수 있다
- 경쟁사의 비공개 수치(유입, 전화, 저장, 광고비, 상담)는 알 수 없다
- AI 답변은 매번 달라진다. 같은 질문을 2~3회 반복해 평균을 본다
- 자동 검색을 반복하면 차단될 수 있어 측정은 필요할 때만, 소량으로 한다
- 후기 조작, 대가성 체험단, 트래픽 조작은 과제 후보에 넣지 않는다
