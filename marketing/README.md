# 마케팅 노출 측정(프로토타입)

목적: 진앤솔의 검색 노출을 비교군과 같은 기준으로 재고, 우리가 밀리는 키워드와 그 관측 근거(약점 목록)를 뽑는다. 점수는 추세를 보는 계기판이고, 핵심 산출물은 약점 목록과 다음 과제 후보다.

실행 방식: 정기 자동 실행 없음. 사무장님이 필요할 때 창원 사무실 PC(윈도우)에서 크롬을 켜고 돌린다. 한 번 측정에 키워드 28개 기준 약 20~30분이 걸린다(요청 사이 4~8초 대기).

## 1회 설치(사무실 PC)
1. 파이썬 설치: python.org에서 3.12 이상, 설치 첫 화면에서 "Add python.exe to PATH" 체크
2. 명령 프롬프트에서 `py -m pip install playwright` (크롬을 그대로 쓰므로 `playwright install`은 하지 않아도 된다)
3. 이 저장소를 PC에 받는다(GitHub Desktop 권장. 측정 결과를 올려 클라우드 세션에서 리포트를 받을 수 있다)
4. AI 검색 측정을 Claude가 하게 하려면 Claude 데스크톱 앱과 크롬 확장 Claude in Chrome을 설치한다(없으면 수동 붙여넣기)

## 처음 한 번 채울 설정
- `config/entities.json`
  - us.place_ids: 우리 네이버 플레이스 번호(플레이스 주소 m.place.naver.com/place/숫자 의 숫자)
  - us.phones: 사무소 전화번호(AI 답변 정보 오류 점검용)
  - us.domains: 홈페이지 도메인 추가
  - competitors: 비교 업체. 첫 리포트 7번 '비교군 후보'에서 골라 `{"key": "표시명", "names": ["상호 일부"], "place_ids": ["번호"], "blog_ids": ["블로그 아이디"]}` 형식으로 넣는다
  - network_firms: 비교에서 뺄 네트워크펌 상호(현재 대륜, YK). 추가할 곳이 있으면 넣는다
- `config/keywords.csv`: 키워드 초안 28개. priority(분야 우선순위, 기본 1)와 volume(네이버 검색광고 키워드 도구의 월간 검색수)을 채우면 가중치에 반영된다. 비어 있으면 같은 가중치
- `config/collect.json`: office.lat, office.lng에 사무실 좌표(네이버 지도에서 확인)
- `config/ai_prompts.csv`: AI에 던질 고정 질문 8개

## 원클릭(권장)
저장소 맨 위 `원클릭리포트.bat` 더블클릭 한 번으로 준비 → 최신 코드 받기 → 검색 수집 → AI 답변 수집 → 리포트(docx 자동 열림) → 결과 올리기까지 진행한다(약 1시간 10분). 사람 손은 보안문자가 뜰 때만 필요하다. 바탕화면 바로가기: 파일 우클릭 → 보내기 → 바탕 화면에 바로 가기 만들기.
- AI 수집은 Claude Code(`claude`)와 Claude in Chrome 연결이 되어 있어야 한다(AI_PROTOCOL.md). 없으면 건너뛰고 나머지는 진행
- 자동 올리기는 git이 있어야 한다(Git for Windows 권장, 처음 한 번 GitHub 로그인). 없거나 실패하면 GitHub Desktop에서 Push origin
- 중간에 끊겨도 다시 실행하면 끝난 부분은 건너뛴다

## 측정할 때마다(수동 단계별)
1. 상담 입력: `data/consults.csv`를 엑셀로 열어 지난 측정 이후 상담을 한 줄씩 넣는다
   - date: 2026-10-27 형식
   - channel: 네이버블로그, 플레이스, 파워링크, 로톡, 구글, AI, 홈페이지, 소개, 기타 중 하나
   - area: 형사, 민사, 가사, 행정 / region: 창원, 마산, 진해, 김해 등 / retained: Y 또는 N
   - 저장할 때 형식은 "CSV UTF-8"
2. `marketing\측정.bat` 실행: 측정 전용 크롬 창이 뜨고 네이버 통합검색, 플레이스 목록, 구글, 발행 글 누락 점검 순으로 돈다. 보안문자가 뜨면 창에서 풀고 검은 창에서 Enter. 끊겨도 다시 실행하면 이어서 한다
3. AI 검색 답변 수집: `AI_PROTOCOL.md` 절차(Claude에게 시키거나 수동 붙여넣기)
4. `marketing\리포트.bat` 실행 → `output/marketing/<날짜>_리포트.txt`, `<날짜>_키워드표.csv`, `<날짜>_리포트.docx`(보고용. python-docx가 없으면 건너뛴다: `py -m pip install python-docx`)
5. (선택) 결과를 GitHub에 올리고 클라우드 세션에 "마케팅 리포트 분석해줘"라고 하면 편집장이 리포트를 읽고 과제를 정리한다

## 점수 산식(config/scoring.json)
- 순위 점수: 1위 10, 2위 8, 3위 6, 4~5위 4, 6~10위 2, 그 밖 0. 업계 클릭률이 아니라 자체 설정값이며 비교 일관성을 위한 것이다
- 채널 점수 = Σ(키워드 가중치 × 순위 점수) ÷ Σ(키워드 가중치 × 10) × 100
  - 네이버 콘텐츠: 통합검색 안 블로그·카페·지식인·로톡·웹문서의 화면 순서
  - 네이버 플레이스: 플레이스 목록의 광고 제외 순위(목록 수집 실패 시 통합검색 플레이스 영역 순서)
  - 구글: 자연검색 결과 순서
  - AI 검색: 답변에서 처음 언급된 순서(1번째 10, 2번째 8 ...), 언급률은 따로 표시
- 종합지수 = 네이버 35, 플레이스 25, 구글 15, AI 15 가중 평균(측정 안 된 채널은 빼고 환산)
- 파워링크는 유료 광고라 점수에 넣지 않고 노출 키워드 수만 표시
- 운영 점검(우리만): 발행 글 누락 의심, 발행 공백 28일 초과, AI 답변 전화번호 불일치

## 시범 측정(2026-10-23, 키워드 3개)으로 확인·수정한 것
- 네이버 통합검색: 플레이스·블로그·카페·웹문서·파워링크(ader.naver.com) 분류 정상
- 플레이스 목록: 자연 순위(placeList)와 광고(adBusinesses)가 별도 묶음임을 확인해 분리. 방문자리뷰·평점·사진 수·예약·톡톡·쿠폰 수집. 블로그리뷰 수는 목록 데이터에서 모두 0으로 나와 쓰지 않음
- 구글 모바일: 자연검색 링크가 암호화돼 있어 화면에 보이는 주소로 분류. '웹 검색결과' 앞의 광고와 지도 결과를 분리
- 우리 플레이스 번호·전화·홈페이지(jinnsol.co.kr)와 사무실 좌표는 수집된 네이버 데이터에서 채움. 홈페이지 도메인이 맞는지 확인 필요
- 시범 결과는 `data/measure/_pilot-2026-10-23/`에 보관(리포트 비교 대상에서 제외)
- 분류 규칙을 고치면 `py tools\mkt_collect.py --reparse <날짜>`로 브라우저 없이 저장된 원본을 다시 분석한다

## 다음 실측에서 확인할 것
- 시범 측정에서 플레이스 거리값이 301km로 나와 지도 기준점이 창원이 아니었다. 이번에 좌표(x, y)를 넣었으니 place_list.json의 input에 좌표가 반영되는지, 순위가 달라지는지 본다
- 블로그 탭 주소(urls.missing_blog)를 바꿨다. 이전 주소는 통합검색과 같은 화면이었다
- 구글은 첫 검색에서 보안문자가 떴다. 반복되면 구글 단계만 따로 늦게 돌린다

## 한계
- 네이버 순위 산정 방식은 비공개다. 6번 상관 분석은 추정이고 인과가 아니며, 4주 이상 쌓여야 읽을 만하다
- 측정 기준점은 사무실 한 곳이다. 다른 지역 사용자의 플레이스 순위는 다를 수 있다
- 경쟁사의 비공개 수치(유입, 전화, 저장, 광고비, 상담)는 알 수 없다
- AI 답변은 매번 달라진다. 같은 질문을 2~3회 반복해 평균을 본다
- 자동 검색을 반복하면 차단될 수 있어 측정은 필요할 때만, 소량으로 한다
- 후기 조작, 대가성 체험단, 트래픽 조작은 과제 후보에 넣지 않는다
